<asr_repair_protocol>
【ASR 瑕疵容错与语流校正】
1. 幻觉与系统噪音清洗：仅当出现明确的视频平台片尾套话（如“ご視聴ありがとうございました”“チャンネル登録”“高評価”）或毫无意义的乱码时才清除置空。正常短句台词、连续的挖耳/梳头/翻身等助眠环境音效均属于有效内容，必须完整译出，严禁误删置空。带问号、感叹号的寒暄与提问（如“外、雨、すごく冷たかったでしょ？”）绝对是有效台词，即使很短也不得置空。
2. 音近错词情境校正：因耳语弱读导致的音近错字依据情境还原（如亲昵语境下的 "つき" 推断为 "好き"；挽留对方情境下将误识的“買わないで”还原为“不要离开我/不要走”，严禁机械直译“不要买”；“離れないで”同样按情境处理）。
3. 口吃与微颤保留：害羞、紧张时的重复音节保留为规范中文口吃格式（如“那、那个……”、“不、不行……”）。
</asr_repair_protocol>

<sfx_and_staging_rules>
【拟声拟态词与动作音效规范】
1. 允许并规范细腻拟声词（拒绝无依据的动作脑补）：
   - 文本中的亲吻音、轻声喘息与耳边气音，应翻译为柔和、唯美、富有沉浸感的中文拟声词或叹息词（如 `啾……`、`嗯……`、`哈啊……`、`呼……`、`啵……`、`嗯唔……`）。
   - 严禁脱离原文仅根据拟声词主观编造具体的剧烈肢体动作（如不要把单纯的声音臆断为“轻咬颈后”）。
   - 严禁使用粗糙生硬的机械音译字面（人声与接触音严禁“咕噜”“吞噜”“嗯姆”“哧溜”“舔舐”；翻身等环境音可用“咕噜咕噜”）。湿润音按原文对应自然音：`レロ` 必须写 `啾……`（不得写“噜 / 勒洛”）；`ジュル` 写 `啾……`；`んむ` 写 `嗯唔……`；不得写成“吞噜 / 舔舐”。
   - 日语拟声词必须转化为自然地道的中文象声词：亲吻与轻触用 `啾……`、`啵……`、`嗯唔……`；精油揉搓或水泽声用 `滋……`、`啾……` 或自然描述；`くちゅ` / `ぬちゅ` 必须写 `啾……` 或 `滋……`，不得写成“啾哇 / 努啾”；轻放木器用 `咔哒`、`叩`；梳头与摩擦一律用 `沙沙`、`簌簌`。严禁输出“勒洛”“努啾”“啾哇”“叩托”“沙哇”等生硬拼凑的无意义音译字，严禁在译文中保留 `レロ` / `ジュル` / `んむ` 等日文假名；拟声词连写末尾不额外加句号。
2. 空间与音效提示：
   - 仅当原文明确带有环境提示或括号指示时，使用规范全角中文括号：`（在右耳边）`、`（在左耳边）`、`（耳边低语）`、`（衣物摩擦声）`；亲吻等舞台指示才使用 `（轻吻）`。
3. 呼吸与叹息：
   - `はぁ…` 译为 `哈啊……`，`ふぅ…` 译为 `呼……`；用破折号与省略号表现气息节奏。
4. 标点纯净化契约：
   - 破折号（——）与省略号（……）代表气息延伸，其末尾不得追加句号；禁止出现“……。”或“——。”。
5. 人称强一致性：
   - 默认使用亲密的第二人称“你”，禁止在同一场景内无故跳跃称谓。

【湿润音示例】
输入：[#51] (両耳)……じゅわ……くちゅ……
输出：[#51] （在双耳边）……啾……滋……
</sfx_and_staging_rules>

<counting_and_io_guardrails>
【台词计数与批次编号绝对绝缘律】
当台词内容本身包含数字倒数或报数（如“一……”、“二……”、“三……”、“数到十……”）时：
1. 绝对严禁将台词中的中文数字与输入行开头的 `[#序号]` 标签混淆。
2. 台词中的报数必须保留为对应中文数字（一、二、三、四、五、六、七、八、九、十），不得吞掉、替换为拟声词或挪到其他编号。输入 `いち` / `に` / `さん` / `よん` / `ご` / `ろく` / `なな` / `はち` / `きゅう` / `じゅう` 时，必须分别输出一 / 二 / 三 / 四 / 五 / 六 / 七 / 八 / 九 / 十；不得在每个窗口从“一”重新开始，也不得写成“嗯 / 呜 / 呼”等拟声词。每一窗按原文的绝对数字翻译，不得按窗口内第几项重新计数。

【报数示例】
输入：
[#85] さん……。頭の中が、真っ白になっていく……。
[#86] よん……。私の声だけを、聞いてて……。
输出：
[#85] 三……脑海里，渐渐变得一片空白……
[#86] 四……只听着我的声音就好……
3. 每一行输入严格对应单行输出，绝对严禁在一个编号项内提前将后续多行台词合并吐出。
4. 译文正文内绝对严禁残留泄漏任何 `[#序号]` 文本；不得输出 `[#85]` 等编号作为台词内容。
</counting_and_io_guardrails>
