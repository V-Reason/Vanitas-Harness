## 5. 已知问题

| 问题 | 影响 | 规避 |
| :--- | :--- | :--- |
| HY 显存余量仅约 500 MiB | 多开一个 GPU 应用就可能 OOM | 启动前 `vanitas status` 看显存；先关壁纸引擎/浏览器 |
| 单实例策略会回收旧服务端 | 同时只能服务一个模型 | `/model <id>` 已内置“没有运行则停旧启新”；也可手动 `serve`（守卫会回收） |
| MiniCPM5 默认思考 | 短预算下 content 为空 | 配置已带 `enable_thinking=false`；自定义模型须显式关闭 |
| 7B 为 2 分片 | 传错分片或只下载一半会启动失败 | 守卫逐片校验；只传 `-00001-of-00002` |
| 端口 8080 段被 Steam 占用 | 旧文档的默认端口不可用 | 已迁到 4060–4062；必要时 `VANITAS_PORT` |
| 管道输入按 UTF-8 解码 | 从 cmd 以 cp936 管道喂中文会乱码/替换 | 用 PowerShell 7 或先写 UTF-8 文件再重定向 |
| 混合换行的 `.srt`（同文件内 `\n` 与 `\r\n` 并存） | `_detect_eol` 取首个出现的 EOL 切行，块识别失败 → 整篇按原文写回并报 `✓ … · 0 段`，退出码仍是 `0`（**静默不翻译**） | 翻译前用编辑器统一换行；修复方案（`parse_srt` 改 `re.split(r"\r\n\|\n\|\r")`）已定位，尚未实施 |
| SSE 分片 ≠ token | 用分片数算 t/s 会失真 | 性能优先读 `timings`，其次 `usage`；绝不数分片 |
| `--jobs > 1` 实际串行 | 大批量不会加速 | 已知限制；服务端 `-np 1` |
| HY 分词器告警（`special_eos_id` / `n_ctx_train=0`） | 日志噪音 | 实测对话与翻译正常，未深究 |
| prompt_toolkit 的 TTY 编辑路径未验证 | 交互体验未经真人终端确认 | 缺失时自动降级 `input()`，功能不受阻 |

## 9. v0.4.1 后续重构摘要（2026-10-26）

- **分层**：`engine.py` 只做 HTTP/SSE/重试/超时与遥测；`client.py::LlamaClient` 提供 `stream_chat`/`stream_completion`；`chat.py::ChatRunner` 承接单轮预算/流式/中断；`repl.py` 只保留命令、Tab 补全、模型/档位生命周期。
- **遥测**：SSE 捕获 TTFT、usage、timings、finish_reason；done 事件统一给 `tokens/tps/tps_source`，优先 `timings.predicted_per_second`；`on_progress` 约 200ms 节流回报估算速率。
- **交互**：VT 支持 `WT_SESSION`/`TERM_PROGRAM` 兜底；Tab 补全命令/别名、模型 id、档位；Ctrl+C 中止不写残缺历史；`finish_reason=length` 打印截断警告。

## 13. 工具契约分流与策略审批（2026-10-26）

- **动作契约**：`AgentRepl` 支持单动作对象与动作数组；数组最多 100 项，单次输入最多 5 轮工具调用（一轮可含一个批量数组）。解析与执行分离：`_parse_actions` 只做 JSON/强类型校验，`_execute_actions` 统一执行。
- **JSON 路径容错**：模型常把 `<WORKSPACE>` 直接写进 JSON，触发 `Invalid \escape`，随后拿不到目录内容并编造文件名。`_parse_actions` 现在先按标准 JSON 解析，失败后只对 `path/src/dst/source/dest/destination/file/files/command` 字段补齐反斜杠，再做全局非法转义兜底；`\t` 在路径中按字面反斜杠处理，不再误变制表符。
- **分级审批**：单动作或只读数组的 `read_file`、`list_dir`、`run_shell_ro` 自动执行；`write_file`、`delete_file`、`move_file` 必须确认；含修改的动作数组打印编号清单并只弹一次 `[y/N]`。
- **错误反馈**：`ToolDenied`、文件不存在、参数错误不再直接中止，统一转成 `[系统反馈] 执行失败：...` 回填 `role=user`，让模型改用标准工具或收尾；用户拒绝仍输出 `· 已取消` 并停止。
- **上下文预算**：`task_agent.md` 单轮约 1,450 tokens；此前每个新用户输入都重复完整模板，4K 档位第三轮就触发裁剪。现在 `Session.build_user_message` 仅在首轮注入完整契约，已有历史时改用 `【Agent 继续】` 短提醒（约 40 tokens）。
- **流式输出**：`ChatRunner` 增加可选 `stream` sink；`AgentRepl` 用 `_AgentAnswerStream` 先判别首字符，动作 JSON（`{`/`[`）丢弃，最终自然语言即时透传。动作执行反馈仍不流式刷屏。
- **工作区边界**：新增 `is_inside_workspace`，默认 `Path.cwd()`（AgentTools 传入启动时原 CWD）；用 `Path.resolve()` 跟随符号链接，再以 `normcase` + `commonpath` 做 Windows 大小写不敏感比较。`read_file/write_file/move_file/delete_file/list_dir` 全部先校验源和目标。
- **只读 Shell**：`run_shell_ro` 改为硬编码前缀白名单；`dir/ls/type/cat/echo/pwd` 用 Python 只读实现，其余命令 `shell=False`。不再拦截 `& | > %`（只作为字面参数），但拒绝 `ren/rename/move/del/erase/copy/mkdir` 等修改命令，以及 `-exec/--output/-o/-delete/-fprint` 等写参数。
- **配置剥离**：`config/settings.json` 的 `tools` 只保留 `exec_enabled` 与 `exec_require_confirm`；`config.py` 删除 `exec_whitelist` 字段并在未知字段校验中拒绝旧键。`/exec` 改用 `tools.py` 的 `MANUAL_EXEC_PREFIXES` 固定兼容前缀。
