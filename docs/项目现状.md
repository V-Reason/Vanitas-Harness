## 5. 已知问题

| 问题 | 影响 | 规避 |
| :--- | :--- | :--- |
| HY 显存余量仅约 500 MiB | 多开一个 GPU 应用就可能 OOM | 启动前 `vanitas status` 看显存；先关壁纸引擎/浏览器 |
| 单实例策略会回收旧服务端 | 同时只能服务一个模型 | `/model <id>` 已内置“没有运行则停旧启新”；也可手动 `serve`（守卫会回收） |
| MiniCPM5 默认思考 | 短预算下 content 为空 | 配置已带 `enable_thinking=false`；自定义模型须显式关闭 |
| 7B 为 2 分片 | 传错分片或只下载一半会启动失败 | 守卫逐片校验；只传 `-00001-of-00002` |
| 端口 8080 段被 Steam 占用 | 旧文档的默认端口不可用 | 已迁到 4060–4062；必要时 `VANITAS_PORT` |
| 管道输入按 UTF-8 解码 | 从 cmd 以 cp936 管道喂中文会乱码/替换 | 用 PowerShell 7 或先写 UTF-8 文件再重定向 |
| SSE 分片 ≠ token | 用分片数算 t/s 会失真 | 性能优先读 `timings`，其次 `usage`；绝不数分片 |
| `--jobs > 1` 实际串行 | 大批量不会加速 | 已知限制；服务端 `-np 1` |
| HY 分词器告警（`special_eos_id` / `n_ctx_train=0`） | 日志噪音 | 实测对话与翻译正常，未深究 |
| prompt_toolkit 的 TTY 编辑路径未验证 | 交互体验未经真人终端确认 | 缺失时自动降级 `input()`，功能不受阻 |

已修复：混合换行 `.srt` 已由 `parse_srt` 的 `splitlines()` 与 `rebuild_srt` 的 EOL 归一化解决（见第 17 节）。

## 13. 工具契约分流与策略审批（2026-10-26）

- **动作契约**：`AgentRepl` 优先解析 `<tool_call>[...]</tool_call>`，同时兼容裸单动作对象与动作数组；数组上限来自 `settings.agent.max_batch_actions`，单次输入步数来自 `settings.agent.max_steps`（默认 10）。`extract_tool_calls` 只做提取，`_parse_actions` 做强类型校验，`_execute_actions` 统一执行。
- **JSON 路径容错**：模型常把 `<WORKSPACE>` 直接写进 JSON，触发 `Invalid \escape`，随后拿不到目录内容并编造文件名。`_parse_actions` 现在先按标准 JSON 解析，失败后只对 `path/src/dst/source/dest/destination/file/files/command` 字段补齐反斜杠，再做全局非法转义兜底；`\t` 在路径中按字面反斜杠处理，不再误变制表符。
- **标签与容错**：模型优先输出 `<tool_call>` 包裹的动作数组；无标签时扫描文中的顶层对象/数组，并用 `JSONDecoder.raw_decode()` 处理尾部垃圾、用栈平衡处理 `{"action":"a"},{"action":"b"}`。`_AgentAnswerStream` 同时抑制标签块、行首裸 JSON 和解释文字后的尾部动作块。
- **分级审批**：单动作或只读数组的 `read_file`、`list_dir`、`run_shell_ro` 自动执行；`write_file`、`delete_file`、`move_file` 必须确认；含修改的动作数组打印编号清单并只弹一次 `[y/N]`。
- **错误反馈**：`ToolDenied`、文件不存在、参数错误不再直接中止，统一转成 `<tool_result>` 中的“执行失败：...”回填 `role=user`，让模型改用标准工具或收尾；用户拒绝仍输出 `· 已取消` 并停止。批量结果逐项列出成功/失败详情。

## 30. 文件名翻译（2026-10-28）

- **纠偏**：上一轮把“翻译文件名”误解为“自定义输出文件名”，已整体回滚 `3a3ce2b`。当前提供两种语义：`--translate-filename` 翻译内容+文件名，`--translate-filename-only` 只改名。
- **内容模式**：`--translate-filename`/`--translate-name` 在正文翻译前译文件名，输出 suffix 强制为空串，因此 `The Clock.md → 时钟.md`、`雨の駅.md → 雨中车站.md`，不再追加 `.zh`；仍只接受 `.txt`/`.md`/`.srt`，`--out-dir`、目录相对层级、输出冲突检查继续沿用。
- **仅改名模式**：`--translate-filename-only`（别名 `--translate-name-only`）原地重命名文件/子目录，不读文件内容、不筛选扩展名，支持 `.mp3`/`.mp4`/`.wav`/`.png`/`.jpg` 等任意文件；不写 `.zh`，拒绝 `--out-dir`。传入根目录本身不重命名，隐藏文件/隐藏目录跳过。
- **进度**：两种文件名模式都用 `Spinner` 逐项显示 `文件名 i/N 原名` / `目录名 i/N 原名`；TTY 有 spinner，管道/非 TTY 落到完成行。正文阶段沿用原有内容看板。
- **系统提示**：`FILENAME_SYSTEM_PROMPT` 为短正向提示：普通英文/日文词照常翻译，已有中文保持；`[[K0]]` 占位符必须原样保留；示例包含 `Hello_World`、`Chapter_01`、`photos_2024`、`トラック①`、`report_临时`。
- **遮罩与还原**：`_mask_name_literals()` 把高置信编号（`<PRIVATE_TRACK>`/`A-12`/`2024-001`）、全大写/内部大写、版本号、`+ # &`、`_临时` 等白名单标记、装饰符号（引号/括号/`！`/`♪`/`♡`/`❤`/`~`/`&` 等）替换为 `[[K0]]`；模型只翻普通词，`_restore_literals()` 逐字恢复。独立数字、普通下划线、`wav` 等技术名不遮罩/不调用模型；纯中文名也不调用模型，避免加词。
- **重试与回退**：`NameTranslation` 返回 `name` 与 `fallback_reason`；仅占位符丢失/重复、截断、空结果或恢复后超 80 字符时最多重试一次，仍失败才保留原名并告警。单文件回退不中止批处理；正文模式回退且无 `--out-dir` 时跳过该文件，避免覆盖源文件。
- **清理**：`sanitize_filename_stem()` 取首行、去 `文件名：`/`翻译：` 前缀、去原扩展名，把 Windows 非法字符替换为 `_`；不再剥外层引号/`『』`，不再做全符号计数否决，长度限制在字面量恢复后检查。
- **状态**：正文模式的译名写入 `TranslationSource.translated_stem`，由 `output_path(..., stem=...)` 统一供规划与写盘使用；仅改名模式用 `NameTarget` / `NameRename`，`apply_name_renames()` 按深度从深到浅、每层临时名两阶段执行，支持同层交换与纯大小写变化。
- **冲突**：正文模式由 `plan_translation_outputs()` 拦截同一目标；仅改名模式由 `plan_name_renames()` 拦截译名重复与已存在目标，均返回 `5`，不覆盖。

### 30.3 未验证边界

- 每个文件/目录名通常一次翻译请求，校验失败时最多再重试一次；未做批量合流，超多文件会增加额外请求数与耗时。
- 遮罩只覆盖高置信编号、全大写/内部大写、版本号、`+ # &`、`_临时` 白名单与装饰符号；独立数字、普通下划线、`_癒し` 等普通标题不遮罩。
- 纯中文/无假名汉字名（`情侣日常`、`大購入特典`、`説明書`）不调用模型，原样保留；这是避免误改中文的取舍，代价是纯汉字日文名可能不翻译。
- 占位符丢失/重复、截断、空结果或恢复后超 80 字符时最多重试一次；仍失败只对该文件保留原名并告警，不中止整批。正文模式无 `--out-dir` 时回退会跳过该文件，避免覆盖源文件。
- 去掉遮罩后没有普通英文/日文词的名称（`NYC_2024`、`<PRIVATE_TRACK>`、`AI简报_v2`）不调用模型，直接原名；`wav`/`mp3` 等技术名保留。
- 符号由占位符保证，不再做全符号计数；未被遮罩的普通下划线仍可能被模型自然改写。
- 仅改名模式是原地重命名：`--out-dir` 被拒绝，传入的根目录本身不重命名，隐藏项跳过；没有 `--dry-run`/`--no-clobber`。
- 仅改名模式按层两阶段重命名；极端 OS 权限/占用错误可能只回滚当前层，之前的深层已提交，未做跨层事务回滚。
- 未单独拦截 Windows 保留设备名（`CON`、`PRN` 等），由文件系统写入错误兜底。
- 正文模式若译名与源文件同名且无 `--out-dir`，会被“输出覆盖输入”检查拒绝；需显式给独立输出目录。
- 正文模式输出已不再带 `.zh`，目录扫描不会自动把它识别为旧产物；同一目录重跑时可能把旧输出当输入并触发冲突，建议使用独立 `--out-dir`。
- 只验证了英文名与日文名到中文；未验证中文名、纯数字名、超长 Unicode 名与 Linux 文件名规则。
