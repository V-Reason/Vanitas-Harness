## 3. 已交付产物

| 文件 | 接口 | 关键约定 |
| :--- | :--- | :--- |
| `scripts\_env_guard.bat` | `<端口> <模型绝对路径>` | 退出码 `0` 通过 / `1` 端口被占 / `2` 模型缺失或非法 / `3` 运行时缺失 / `4` 旧实例未退出 / `9` 参数错误；顺序为 bin → 模型 → 杀旧实例 → 端口 |
| `scripts\run_qwen2.5_7b_q6.bat` | `[模型路径] [档位]` | 端口 8080；档位 1=4K+Q8_0 KV（默认）、2=8K+Q4_0 KV、3=4K+F16 KV |
| `scripts\run_minicpm5_2b_q6.bat` | `[模型路径] [档位]` | 端口 8081；档位 1=8K+F16、2=32K+F16 |
| `scripts\run_hymt2_7b_q6.bat` | `[模型路径] [档位]` | 端口 8082；档位与 Qwen 同构 |
| `scripts\engine_control.bat` | 菜单 `[1]-[7]` | 启动派生独立窗口；`[4]` 停止并复测；`[5]` 状态；`[6]` 3B 临时验证 |
| `tests\multi_model_benchmark.py` | `--port --host --timeout --wait --runs --suite --json-out` | 退出码 `0` 通过 / `1` 未就绪 / `2` 协议或性能失败 / `3` 质量失败 / `4` 参数错误 |

环境变量（启动器生效）：`VANITAS_PORT` 覆盖端口、`VANITAS_PROFILE` 覆盖档位。两者都存在默认值，不设置即生产行为。

统一 llama-server 参数（三个启动器一致）：

```bat
llama-server.exe -m "<模型>" --host 127.0.0.1 --port <端口> ^
    -c <ctx> -ngl 999 -np 1 -fa on ^
    -ctk <KV> -ctv <KV> ^
    -a "<模型别名>" -fit off --metrics
```

> `-fa on` 与 `-fit off` 都是踩坑后的显式写法：本 build 裸传 `--flash-attn` 会直接退出，`--log-format` 根本不存在；`-fit` 在已指定 `-ngl` 时只会打印失败告警。

## 6. 已知问题与规避

| 问题 | 影响 | 规避 |
| :--- | :--- | :--- |
| 8080 被 `steamwebhelper.exe` 占用（PID 34724） | Qwen 主力端口无法启动 | 退出 Steam，或 `set VANITAS_PORT=8090` 后启动 |
| 本机 `bin\` 为 build 11853 | 上游文档里的 `--log-format`、裸 `--flash-attn` 均不可用 | 已修正；升级 `bin\` 后先跑守卫 + 3B 冒烟再交付 |
| llama-server 无 API Key 且 CORS 全开 | 仅绑定 `127.0.0.1`，但同机任意进程可调用 | 不将端口映射到局域网；如需共享须加反向代理与鉴权 |
| 3B 翻译不稳定 | 宽松提示下会输出英文或追加注释 | 评测已限定“只评首段 + 严格提示 + 温度 0”；生产翻译请用 8082 |
| SSE 分片 ≠ token | 用分片数算 t/s 会系统性失真 | 性能只读服务端 `timings`/`usage`，分片仅用于流式协议检查 |
