# Vanitas-Harness 用户使用手册

> 适用版本：`v0.4.1` · 平台：Windows 11 + RTX 4060 Laptop（8 GB）
> 架构与契约见 [总设计方案.md](总设计方案.md)；已知限制与验证边界见 [项目现状.md](项目现状.md)。

---

## 1. 前置条件

| 项 | 要求 | 检查 |
| :--- | :--- | :--- |
| Python | ≥ 3.10 | `python --version` |
| prompt_toolkit | 唯一第三方依赖 | `python -c "import prompt_toolkit; print(prompt_toolkit.__version__)"` |
| llama.cpp | `bin\` 下有 `llama-server.exe`、`llama.dll`、`ggml-base.dll`、`ggml-cuda.dll` | `dir bin` |
| 权重 | 按 `config\models.json` 的路径放入 `models\` | `vanitas models` 会打印路径 |
| 显存 | 空载底噪建议 < 1.5 GiB；HY 需要约 7.7 GiB | `nvidia-smi` |

安装唯一依赖：

```powershell
python -m pip install prompt_toolkit
```

未安装也能运行：REPL 自动降级为 `input()`，失去历史与行编辑，其余功能不变。

## 2. 第一次启动

在仓库根目录（或任意目录调用根目录的 `vanitas.bat`）：

```bat
vanitas.bat
```

直接执行 `vanitas` 默认进入 Agent 闭环：使用 `settings.defaults.agent` 指定的 `qwen_coder`（8K/Q8 主力），没有运行中的服务端时自动启动。需要纯聊天 REPL 时用 `vanitas chat`，默认使用 `settings.defaults.chat` 指定的 `qwen7b`（非 Coder 通用模型）。translate 默认 `hymt`，batch 默认 `qwen7b`。启动后 CLI 会：

1. 跑守卫（DLL → 模型/分片 → 回收旧实例 → 端口）；
2. 后台启动 `llama-server`，日志写入 `~/.vanitas/logs/`；
3. 轮询 `/health`（终端里显示覆盖式进度 `⋯ 正在加载模型 3.2s`），就绪后打印 `✓ 就绪 · N.Ns` 并进入提示符 `qwen_coder@1 [ctx: 0%] › `。

常用起手式：

```bat
vanitas.bat models                  :: 看模型、端口、档位、别名
vanitas.bat status                  :: 看进程、端口、显存
vanitas.bat serve qwen7b            :: 后台启动并等待就绪
vanitas.bat chat --model minicpm    :: 直接进入 REPL（未启动会自动拉起）
vanitas.bat stop                    :: 结束所有 llama-server
```

`vanitas.bat` 只做四件事：记录原 CWD、切到仓库根、调用 `python -m vanitas`、透传退出码。除 Agent 的 `{cwd}`/沙盒根外，`python -m vanitas ...` 与其等价。

## 3. 命令速查

| 命令 | 作用 | 示例 |
| :--- | :--- | :--- |
| `vanitas` | 默认进入 Agent 受控闭环（`settings.defaults.agent`=`qwen_coder`） | `vanitas` |
| `vanitas chat` | 交互式 REPL（`settings.defaults.chat`=`qwen7b`）；必要时自动启动服务端 | `vanitas chat --model qwen7b --task chat` |
| `vanitas models` | 列出模型/端口/档位/别名/路径与四模式默认路由 | `vanitas models` |
| `vanitas status` | 进程、端口、显存、运行记录 | `vanitas status` |
| `vanitas serve <id>` | 启动并等待 `/health` | `vanitas serve hymt --profile 2` |
| `vanitas serve <id> --foreground` | 前台运行，Ctrl-C 退出 | `vanitas serve hymt --foreground` |
| `vanitas stop` | 停止所有 `llama-server` | `vanitas stop` |
| `vanitas agent` | 与默认入口等价的 Agent 受控闭环（`settings.defaults.agent`=`qwen_coder`） | `vanitas agent --model qwen_coder` |
| `vanitas translate <文件或目录...>` | txt/md/srt 批量翻译；目录递归；`--translate-filename` 翻译内容+文件名（不加 `.zh`）；`--translate-filename-only` 只原地改名 | `vanitas translate .\media --translate-filename-only` |
| `vanitas batch <tasks.jsonl>` | JSONL 批处理；默认 `settings.defaults.batch`=`qwen7b` | `vanitas batch tasks.jsonl --model qwen7b` |
| `vanitas --version` | 版本 | `vanitas --version` |

全局可选 `-v` / `--verbose`（`serve`、`stop`、`status`、`chat`、`agent` 均可，写在子命令前后都生效）：额外显示 PID、日志路径、监听地址、完整启动参数，以及回答的首字延迟。默认只显示结论，例如 `✓ 就绪 · 12.4s`。

退出码：`0` 成功 / `1` 用户中断 / `2` 配置错误 / `3` 守卫失败 / `4` 参数错误 / `5` 引擎或网络失败。

守卫拒绝统一返回 `3`，**退出码是唯一机读契约**；人读消息首行以 `✗` 开头，提示行以 `·` 开头，不再带 `[GUARD-CODE=N]` 这类前缀，避免脚本解析消息文本。

## 4. REPL 详解

### 4.1 规则

- 只有「以 `/` 开头且第 2 个字符不是空格」的行是命令；其余整行都发给模型。
- 想提问「/model 是什么意思」时，前面加任意文字即可（如「请问 /model 是什么」）。
- 提示符 `模型@档位 [ctx: N%] › `（Agent 默认 `qwen_coder@1`，chat 默认 `qwen7b@1`）。`[ctx: N%]` 只显示上下文占用百分比：<60% 灰、60–80% 黄、≥80% 红（阈值可由 `settings.repl.ctx_warn_pct` / `ctx_danger_pct` 调整）。空闲休眠时追加 `[休眠]`，输入任意内容自动唤醒；服务端没有运行时仍可用 `/model`、`/status`、`/help` 等本地命令。
- 安装 `prompt_toolkit` 时支持 Tab 补全：`/` 补全命令与别名，`/model ` 补全模型 id，`/profile ` 补全当前模型档位。
- Ctrl+C 可中止当前生成；残缺输出不会写入会话历史，下一轮输入继续正常响应。

### 4.2 命令

`/help` 按四组展示：**会话**（`help` / `clear` / `undo` / `save` / `load` / `quit`）、**模型与档位**（`model` / `profile` / `restart` / `stop` / `shutdown`）、**诊断**（`status` / `system` / `task`）、**工具**（`exec`）。命令表本身不变，分组只影响 `/help` 展示。

| 命令 | 说明 |
| :--- | :--- |
| `/help` | 列出全部命令（由命令表自动生成） |
| `/model` | 列出 4 个模型与运行状态；`*` 标记当前模型 |
| `/model hymt` | 切换模型；目标已运行时直连，没有运行时自动停旧启新（显示 `停止旧服务` → `启动 hymt` → `已切换`）；更新 `last_used_model` |
| `/profile` | 查看当前档位、待生效档位与可选档位 |
| `/profile 2` | 设置**待生效**档位并立即写入 `~/.vanitas/preferences.json`；执行 `/restart` 才改变当前服务端 |
| `/restart`（`/reload`） | 有未保存会话时 `[Y/n/c]` 拦截；确认后停旧启新并应用待生效档位 |
| `/system` | 显示当前系统提示 |
| `/system 你只回答一句话` | 设置系统提示文本 |
| `/system prompts\我的提示.md` | 从文件读取系统提示 |
| `/task` | 查看当前任务与可用任务 |
| `/task translate` | 应用 `config\prompts\task_translate.md`，此后每轮输入填入 `{input}` |
| `/clear` | 清空对话，保留系统提示与任务模板 |
| `/undo`（`/pop`、`/rollback`） | 回滚最近一轮完整人类输入 + 全部中间工具调用/回显 + 最终答复，立即释放 tokens |
| `/save` | 保存到 `~/.vanitas/sessions/<时间>.json` |
| `/save <WORKSPACE>\chat.json` | 保存到指定路径 |
| `/load <WORKSPACE>\chat.json` | 加载会话（恢复模型、档位、系统提示、任务） |
| `/exec dir config` 或 `!dir config` | 在用户原生 shell 中执行，无白名单/目录限制，见 4.3 |
| `/stop`（`/kill`） | 停止服务端，仍留在 REPL |
| `/shutdown`（`/halt`、`/exit all`） | 自动保存脏会话 + 停止全部服务 + 退出 CLI |
| `/status` | 模型/档位/端口/视窗进度条/GPU/PID-RSS-uptime/TTFT-tps/Agent 步数/空闲倒计时 |
| `/quit`（`/exit`） | 退出 REPL，后台服务保留；Ctrl-D 等价 |

`/status` 默认输出 4 行紧凑视图：

```text
· 模型 qwen_coder · 档位 1 · 8K + Q8_0 KV（近无损，主力推荐）
· 端口 4060  ✓ 就绪 · 显存 7,000 / 8,188 MiB
· 视窗 █████░░░░░░░░░░░░░░░ 24.1% · 已用 1,972 / 上限 8,192 tokens
· Agent 步数 0/10 · 最近 TTFT 68 ms · 生成 36.4 t/s
```

`/status -v` 或全局 `-v` 模式输出完整展开（含 PID/RSS/uptime/records 明细/待生效档位/空闲倒计时/折叠计数/会话条数），与旧版一致。

状态列统一为极简符号：`✓ 运行` 绿色、`⚠ 残留` 黄色、`✗ 停止` 红色；`/status` 的就绪状态为 `✓ 就绪` 或 `✗ 停止`。提示行使用 `·`，不再使用旧的提示前缀。

### 4.3 使用 `/exec`

`/exec` 与 `!<cmd>` 面向**人类用户**，使用原生 `shell=True`，不再受 `manual_exec_prefixes`、目录或破坏性路径限制；完整支持管道、重定向、`cmd`/`powershell` 调用：

```bat
/exec dir | findstr srt
!git status --short
!powershell -Command "Get-ChildItem *.py"
```

- 保留 `tools.exec_enabled` 总开关与 `exec_require_confirm` 确认；拒绝时输出 `· 已取消`。
- 工作目录优先 `VANITAS_ORIG_CWD`（启动时的用户原目录）；超时复用 `request.timeout_sec`，stdout/stderr 仍各做 512 KiB 字节折叠。
- 这是面向本机工程师的完全信任通道；命令由你输入，不经过模型，**不要把它误当成 Agent 沙箱**。
- `AgentTools.run_shell_ro` 与 `read_file/write_file/...` 仍保持只读白名单、`is_inside_workspace` 边界与写参数黑名单；人类 `/exec` 的开放不会放宽模型工具。
- Agent 的 `read_file` / `list_dir` 上限仍来自 `tools.max_read_bytes` / `tools.max_list_entries`；`move_file` 的非法字符来自 `tools.move_illegal_chars`。

### 4.4 上下文与输出

- 历史预算 = `min(档位 ctx, settings.repl.max_context_tokens) - context_reserve_tokens`（默认 512）；超出时从最早一轮丢弃，并打印 `⚠ 上下文已满，丢弃最早 N 轮对话`。
- 单轮输出预算 = `max(min_output_tokens, 档位 ctx - 历史 tokens - context_reserve_tokens)`，默认最低 256；不再使用旧的 128/1024 静态夹断。
- 首字到达前在 stderr 显示 `⋯ 正在生成 Ns`；首字上屏时立刻擦除，stdout 只留模型输出。
- 回答流式输出；结束后打印 `· token 数 · 耗时 · t/s`。token 优先取服务端 `usage`，t/s 优先取 `timings.predicted_per_second`，缺失时才用本地耗时估算；不会用 SSE 分片数冒充 token。
- `-v` 时在 meta 行追加 `首字 N ms`；`finish_reason=length` 时追加 `⚠ 达到长度上限，输出被截断`。
- Ctrl+C 中止当前生成，残缺内容不上屏为会话历史；下一次输入正常。
- 代码块以 4 空格缩进显示，围栏标记本身不上屏，便于直接复制。

### 4.5 外观：颜色与符号

默认主题下每条结果都以符号开头：

| 符号 | 含义 | 颜色 |
| :-: | :--- | :--- |
| `✓` | 成功（就绪、已保存、已完成） | 绿 |
| `✗` | 失败（守卫拒绝、引擎错误） | 红 |
| `⚠` | 警告（清理旧实例、上下文裁剪、部分失败） | 黄 |
| `⋯` | 进行中（加载、生成、翻译） | 黄 |
| `·` | 元信息、提示与下一步 | 亮黑（暗） |

控制方式见 `config\settings.json` 的 `ui` 段：

```json
"ui": {
  "color": "auto",
  "theme": { "prompt": "cyan", "success": "green", "error": "red", "warn": "yellow",
             "info": "cyan", "muted": "bright_black", "accent": "magenta" }
}
```

- `color`：`auto`（默认，stdout 与 stderr 都是终端时上色）/ `always`（强制，含重定向）/ `never`（纯文本）。
- `theme` 的 7 个键必须同时给出；颜色名限 `black…white`、`bright_*`、`default` 共 17 个（见 `vanitas\ui.py`）。
- 整个 `ui` 段可删：缺省时回落内置默认主题，旧配置不需要迁移。
- 颜色经 `ctypes` 打开 Windows 控制台 VT 解析；`WT_SESSION` / `TERM_PROGRAM` 存在时直接视为现代终端；重定向时 `auto` 自动降级为纯文本。

### 4.6 Agent 受控闭环

直接执行 `vanitas` 等价于 `vanitas agent`。它复用 REPL 与 `config\prompts\task_agent.md`，模型优先输出 `<tool_call>` 包裹的动作数组：

```text
<tool_call>
[{"action":"write_file","parameters":{"path":"a.txt","content":"hello"}}]
</tool_call>
```

- 动作契约：`read_file`、`read_file_range`、`grep_workspace`、`patch_file`、`write_file`、`move_file`、`delete_path`（`delete_file` 兼容别名）、`list_dir`、`run_shell_ro`。模型返回普通中文文本即视为最终答复；标签与原始 JSON 不上屏，最终答复按 token 流式上屏。
- 高阶工具：`patch_file` 用于已有文件的唯一片段替换（避免全量重写）；`read_file_range` 按行区间读取大文件；`grep_workspace` 跨文件正则检索。三者均受工作区路径边界约束；`grep_workspace` 跳过符号链接/忽略目录/超大文件。
- `delete_path` 可删除文件或递归删除目录（如 `__pycache__`）；符号链接只删链接本身，工作区根目录硬拒绝。`delete_file` 仍作为兼容别名。
- 解析器优先取 `<tool_call>` 内容；无标签时兼容裸单动作对象/数组，并可用 `raw_decode` + 栈平衡恢复“解释文字 + 动作 JSON”、尾部垃圾和多个顶层对象。模型仍应先 `list_dir` 再批量修改，不得编造 `a.md/b.md/c.md`。
- JSON 中的 Windows 路径应写成 `<WORKSPACE>` 或 `T:\\TMP\\test`；模型若误写单反斜杠，解析器会对路径字段做有限补齐。
- **解析自愈**：动作解析失败时，系统会把结构化纠偏提示（要求仅输出合法 `<tool_call>` JSON，路径用 `/` 或 `\\`）回灌给模型，最多 2 次；中途成功即清零，2 次后仍失败才打印错误并停止，不会无限重试。
- **停滞熔断**：同一动作与参数连续出现 3 次、A-B-A-B 第 4 步、A-B-C-A-B-C 第 6 步、最近 6 步同签名 ≥3 次，或批次级重复/乒乓，立即熔断并停止；分别提示“连续/震荡/重复/批次停滞”。第 3 次不会执行。
- **超长输出**：底层 stdout/stderr 在解码前按 512 KiB 折叠（前 1/4 + 后 3/4）；回填反馈再按头 20 行/尾 40 行折叠。中间会显示「已截断」标记，首尾与报错堆栈保留，避免冲垮上下文。
- **自动放行**：单个或数组内的 `read_file`、`read_file_range`、`grep_workspace`、`list_dir`、`run_shell_ro` 直接执行，不弹 `[y/N]`；终端显示 `· 自动执行：...`。只读数组不会因为“数组”形态而多一次确认。
- **强制确认**：`write_file`、`patch_file`、`delete_file`、`delete_path`、`move_file` 先展示计划，再要求 `[y/N]`，只接受 `y/yes/是`。
- **失败动作阻断**：本轮内曾失败的动作若以完全相同参数再次提交（即使中间穿插 `read_file_range`/`list_dir`），不弹确认、不执行，直接回填“此前已失败，严禁相同参数重复提交”；修改参数或换策略后可恢复。
- **批量修改**：动作数组里只要含 `write_file`、`patch_file`、`delete_file`、`delete_path`、`move_file`，终端打印编号清单并只弹一次 `[y/N]`；全只读数组自动执行。多文件创建/批量写入优先在同一轮数组提交（单轮批量提交军规）；系统逐项执行并逐项反馈，失败不回滚已成功项，不是事务。
- 执行结果（含 stdout/stderr、读写字节数、移动/删除结果、逐项成功/失败详情）以 `<tool_result>...</tool_result>` 作为 `role=user` 回填；越界、参数错误、`ToolDenied` 也转成失败反馈，让模型改用标准工具或收尾，而不是立即中止。
- `move_file` 的源不存在，或路径含 `#`、`<>"|?*`、控制字符时，会明确返回“源文件不存在或路径非法”，不要继续猜测文件名。
- **重命名/改扩展名只能 `move_file(src, dst)`**；`patch_file` 只替换文件内容，不能改文件名或扩展名。把 `.srt` 改成 `.md` 时，模型不应反复读取后仍用 `patch_file`。
- 单次输入最多 `settings.agent.max_steps` 轮工具调用（默认 10，一轮可含一个批量数组）；达到上限打印 `· 已达最大步数 N`。用户拒绝输出 `· 已取消`，不再自动请求模型。
- 首轮注入完整 `task_agent` 契约；后续用户输入只带 `config\prompts\agent_continue.md` 短提醒，避免每轮重复约 **1,110 tokens** 的模板（续轮约 **110 tokens**）导致 4K 档位快速裁剪上下文。
- 动作审批来自 `settings.agent.auto_actions` / `confirm_actions`；`action_aliases` 可保留旧动作名；反馈截断长度来自 `max_feedback_chars`。
- `/undo`（`/pop`、`/rollback`）从末尾持续弹出，跳过 `<tool_result>`/`[系统反馈]` 中间回显，直到真正的人类 user 为止，整轮原子回滚；清空最近动作窗口并立即释放 tokens，只影响会话历史，不停服务、不改模型。
- 【测试执行规范】模型运行 Python 验证时必须使用 `run_shell_ro("python -m unittest <测试文件>")`；裸 `python <脚本>` 仍被拒绝，这是安全设计。
- 提示符常驻 `[ctx: N%]`，60% 转黄、80% 转红；`/status` 展示视窗进度条、GPU、PID/RSS/uptime、TTFT/tps 与 Agent 步数配额。
- 会话超过 65% 时，系统自动把早于最近 2 轮、超过 1000 字符的旧 `<tool_result>` 折叠为锚点；`<tool_call>` 动作与最近两轮保留，需要细节时模型应重新调用工具。
- 当前时间仍以 `{date}` 注入用户任务模板，系统提示保持静态，避免秒级时间戳破坏 KV Cache 前缀。
- 提示词格式按模型选择：`system_default` 全静态纯文本；`task_chat/task_code/task_agent/task_translate_asmr` 使用 XML；`task_translate` 与 `agent_continue` 保持纯文本/紧凑提醒。`task_agent` 的批量是逐项执行而非事务；`patch_file` 只要求唯一片段，不强制固定上下行数；不提供 `_reason` 参数。
- 沙盒根是启动时的用户原工作目录（由 `vanitas.bat` 的 `VANITAS_ORIG_CWD` 透传，而不是切回仓库根后的目录）；所有文件工具统一经过 `is_inside_workspace`，用 `Path.resolve()` + `normcase/commonpath` 拦截父目录、绝对越界、跨盘符与符号链接。
- `run_shell_ro` 只允许 `tools.readonly_shell_prefixes`（默认 `dir/ls/type/cat/echo/findstr/find`、`git status/log/diff` 等），拒绝 `ren/del/move/copy/mkdir` 等修改命令；`-exec`、`--output`、`-o`、`-delete`、`-fprint` 等写参数由 `readonly_blocked_flags` / `readonly_blocked_prefixes` 拦截。它使用 `shell=False`，`& | > %` 只作为字面参数，不会串联命令或重定向写文件。
- **白名单分层**：`tools.readonly_shell_prefixes` 是通用只读命令；`tools.project_prefixes` 是项目特定脚本（如 `python verify.py`）。`run_shell_ro` 白名单 = 两集合的并集。把 `python verify.py` 放在 `project_prefixes` 而非 `readonly_shell_prefixes`，是为了让通用 Harness 默认值保持干净，项目通过 settings 自行扩展。
- 修改文件/目录必须使用 `move_file` / `delete_path`（`delete_file` 兼容）/ `write_file`；提示词明确禁止用 `ren`、`del`、重定向等 shell 写操作。用户说“用 shell 把 a.txt 改成 b.txt”时，模型应改用 `move_file`；硬试 `ren` 会被拒绝并收到反馈。
- 当前时间以 `{date}`、工作目录以 `{cwd}` 注入模板。
- 路径约束是参数级防御，不是 OS 级沙箱；真实模型是否稳定遵守 JSON 契约仍需人工验收。

## 6. 翻译

```bat
vanitas.bat translate novel.md --preset prose      :: 小说/散文，8K Q4，10 条上下文
vanitas.bat translate a.srt --preset subtitle       :: 普通字幕（默认），8K Q4，12 条上下文
vanitas.bat translate audio.srt --preset asmr       :: ASMR 字幕，6 行合流
vanitas.bat translate a.srt --preset general        :: 旧版 4K Q8 / 5 条上下文
vanitas.bat translate a.srt --model qwen7b          :: 用通用模型兜底
vanitas.bat translate .\novels --preset prose --out-dir .\translated
                                                    :: 递归翻译整个目录，保留子目录层级
vanitas.bat translate .\novels --translate-filename --out-dir .\translated
                                                    :: 翻译内容+文件名；输出不加 .zh
vanitas.bat translate .\media --translate-filename-only
                                                    :: 只原地翻译文件名/目录名；支持 mp3/mp4/png 等任意文件
```

- 正文翻译模式下支持 `.txt` / `.md` / `.srt`；默认使用 `settings.defaults.translate` 的 `hymt`。输入文件、`--out-dir`、`batch` 的 JSONL、`--system` 与 `--config-dir` 的相对路径均按**启动 `vanitas.bat` 时的原工作目录**解析，而不是仓库根。
- 正文翻译模式下输入可以是文件、目录，或任意混用。目录会递归展开，只收 `settings.translate.source_suffixes` 中的文件；其他扩展名跳过。目录中已有的 `<原名><output_suffix>.<扩展名>`（如 `a.zh.md`）视为上次产物并跳过，不会翻成 `a.zh.zh.md`；显式点名的 `a.zh.md` 仍会翻译。
- 正文翻译模式下 `--out-dir` 存在时，目录输入会保留相对层级（`novels/sub/a.md → out/sub/a.zh.md`），直接指定的文件仍平铺在输出根。若两个输入会写到同一目标（典型是两个同名文件、不同目录、平铺到同一输出根），会在启动模型前报 `输出路径冲突` 并返回 `5`；输出目标若等于任一输入文件也会拒绝，避免覆盖。
- 正文翻译模式下目录递归不会进入 `--out-dir` 自身；空目录或只含已生成译文的目录会报 `没有可翻译文件` 并返回 `5`。完成行中的源文件名带目录相对路径（如 `sub/a.md → a.zh.md`），便于区分同名文件。
- `--translate-filename`（别名 `--translate-name`）翻译文件内容**和**文件名，输出**不再追加 `.zh`**：`The Clock.md → 时钟.md`、`雨の駅.md → 雨中车站.md`。仍只接受 `.txt` / `.md` / `.srt`，`--out-dir` 与目录相对层级继续生效；若译名与源文件同名（无 `--out-dir` 时），会报“输出会覆盖输入”并返回 `5`，建议使用独立输出目录。
- `--translate-filename-only`（别名 `--translate-name-only`）**只原地重命名**文件/子目录，不读也不翻译文件内容，因此支持 `.mp3` / `.mp4` / `.wav` / `.png` / `.jpg` 等任意扩展名；同样不加 `.zh`。该模式不接受 `--out-dir`，传入的根目录本身不重命名，只处理其下文件和子目录；隐藏文件/隐藏目录跳过。译名冲突或目标已存在时整批在写盘前拒绝，返回 `5`。
- 两种文件名模式都会逐项显示进度：TTY 下显示 `文件名 i/N 原名` / `目录名 i/N 原名` 的 spinner，完成后落一行 `→ 译名`；管道/非 TTY 只输出完成行。正文翻译阶段使用文件级看板与批处理汇总报告。只改名模式收尾输出 `名称翻译完成 · 共 N 项 · 重命名 R · 保留原名 F · 失败 E`。
- 文件名翻译使用短、正向的专用系统提示，并用 `[[K0]]` 占位符把高置信编号（`<PRIVATE_TRACK>`、`A-12`、`2024-001`）、全大写/内部大写、版本号、`+ # &`、`_临时` 白名单和引号/括号/`！`/`♪`/`♡`/`❤`/`~` 等装饰符号先遮罩；模型只翻译普通词，完成后逐字恢复。因此 `Hello_World → 你好_世界`、`Chapter_01 → 第01章`、`photos_2024 → 照片_2024`、`report_临时 → 报告_临时` 可正常翻译，而 `“”`、`『』`、`【】`、`♪` 不会被删掉。
- 纯中文/无假名汉字名（如 `情侣日常`、`私密掏耳`、`大購入特典`）和 `wav`/`mp3` 等技术名不调用模型，原样保留；纯汉字日文名可能因此不翻译。去掉遮罩后没有普通英文/日文词的名称也直接返回原名且不调用模型。
- 清理器不再剥外层引号/`『』`，只去 `文件名：`/`翻译：` 前缀、原扩展名和 Windows 非法字符；占位符丢失/重复、截断、空结果、恢复后超 80 字符，或含假名的名称完全未翻译时最多重试一次，仍失败才保留原名并告警。正文模式回退且无 `--out-dir` 时会跳过该文件，避免覆盖源文件。
- 预设优先级：显式 `--model` / `--profile` > `--preset` 中的档位 > 全局默认/偏好。预设要求 8K Q4，而当前服务是 4K Q8 时，`translate` 会自动停止旧服务并启动目标档位；启动失败会返回非零，不会静默使用旧档位。
- 预设表：

| preset | 场景 | 模型档位 | 上下文 | chunk | 窗口 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `subtitle`（默认） | 普通字幕 | HY-MT2 profile 2，8K Q4 | 12 条 | 800 字符 | 1 行 |
| `prose` | 小说/散文 | HY-MT2 profile 2，8K Q4 | 10 条 | 800 字符 | 1 段 |
| `asmr` | ASMR 字幕 | HY-MT2 profile 2，8K Q4 | 12 条 | 800 字符 | 6 行 / ≤250 字符 / 后文参考可选（默认关） |
| `general` | 旧版兼容 | HY-MT2 profile 1，4K Q8 | 5 条 | 1500 字符 | 1 行 |

- `.txt` / `.md`：按空行分段；段内超过预设 `chunk_chars` 时按句末标点再切；原文空行结构保留。`prose` 默认 800，`general` 保持 1500。
- `.srt`：只翻字幕文本；序号、时间轴、空行与 BOM 保留；行尾统一为检测到的 EOL（混合 CRLF/LF 也可解析）；多行字幕整体翻译并保留行结构。
- `--preset asmr`：选择 `task_translate_asmr.md`，自动启用多句合流（W=6，窗口 ≤250 字符）；可选 `lookahead_cues`（0–4，默认 0）把下一窗若干条原文作为只读后文参考；后文只进入 `<reference_context>`，不进入待翻译输入、不写历史/写回。覆盖 Whisper 片尾幻觉/循环套话清洗、接吻/喘息拟声词、口吃保留、`（在耳边低语）` 等全角动作括号，以及 `梵天`/`膝枕`/`添寝`/`特典小剧场` 等圈内文化词与 `浅いところ`/`お騒がせ` 等容易误译的表达；这些词保留原词并约束自然搭配，不做过度意译。新增 `<sensory_immersion>` 约束贴耳呼吸感、体感具象（化掉/麻酥酥）、动作本土化（扑倒/使坏）与跨行语流；明确普通片假名不是专名、拟声词不得保留假名、禁止 `SEXPAR`/`Track` 与斜杠并列。12 条上下文指 **12 条 cue**，不是 12 个 6 行批次。
- ASR 硬清洗：命中 `ご視聴ありがとうございました` / `チャンネル登録` / `高評価` / `ベルマーク` / `Thank you for watching` / `Please subscribe` / `Sous-titres` 的字幕块直接置空，不调用模型，保留原序号与时间轴；空字幕会以标准时间轴空行写回。
- 合流结果必须按 K 个 `[#序号]` 编号项对齐；某编号清洗为空时输出 `[#N]` 空正文，不能删除编号；缺项、多翻、重复或乱序时该窗口自动回退逐句串行，时间轴与序号不变。若模型每窗从 `[#1]` 重新编号，且数量/顺序完整，引擎会按位置恢复。
- 窗口结构守卫：译文正文任意位置出现 `[#N]`、非空原文得到空译文，或同一窗口内“不同原文却得到完全相同且足够长的译文”时，整窗不采用，自动回退逐句重译；逐句结果在 cue 边界清理 `[#N]`。这用于拦截编号正确但内容错位/复制相邻行的窗口。批次响应本身保留编号，`sanitize_translation_output` 不再全局删除 `[#N]`。
- cue 级静默后处理：繁体字转简体、行首 `，、；：。！？` 清理、`……。`/`~。` 等重复句号清理、原文无括号时剥除虚构动作括号；开头 `……`/`——`、原文已有括号与清洗后为空的内容会保留。只改字幕正文，不动序号/时间轴。
- 文档级实体译法：ASMR 合流只以敬称名、`という名`/`役` 明确姓名和共同前缀汉字姓名建立实体索引；裸片假名/拟声词/普通名词不建实体，`トラック`/`セックス`/`バイバーイ` 等不会因重复出现被锁成专名。首次高置信出现的译名会作为“锁定译名”，后续窗口 Prompt 附带实体变体、锁定名与前文示例；平假名写法仅在命中明确姓名时作为别名。它只清理未翻译的日文专名，不保证中文译名变体 100% 自动替换；仍建议人工抽检长文本专名。
- 写回硬校验：译文含空行、日文假名、`SEXPAR`/`SEXXPAR`/`Track` 或中日文斜杠并列时，该窗口不写回并整窗回退逐句；单句回退仍不合格则保留原文并记失败。`ASMR`/`NG`/`BGM` 与数字分数不误伤。
- 术语与语域（P1/P2a，ASMR 预设）：`config\glossary\asmr.tsv` 是术语表（`source<TAB>preferred<TAB>forbidden`，`#` 开头为注释，forbidden 用 `|` 分隔）。只有源文命中 source 时才把译文里的 forbidden 替换成 preferred（例如 `アマアマ` 场景把“业余水平/业余”改成“甜腻”；`お耳をマッサージ` 的“采耳”改成“耳朵按摩”，仅 `マッサージ` 时改成“按摩”；`耳かき` 不受影响）；preferred 没出现不会触发重译，术语表也不进 Prompt。文档语域按固定词表判定：服务语境（`いらっしゃいませ`/`お客様`/`予約` 等）保留“您”，亲密语境（`先輩`/`好き`/`膝枕` 等）自动把“您”统一成“你”，证据不足时不动称谓。
- 文档级重复守卫：同一文件内“不同原文却复用相同/高度相似译文”会被文档级索引发现，每个问题 cue 最多触发一次定点重译（提示“禁止复用”，并同时给出重复条与本条原文片段）；重译仍不合格则保留原译，不记为失败。另有一条窄补充：源文规范化相似度 ≤0.5 且译文共同前缀 ≥6 字也判重复（可检测 `自由談 #80` 这类长共同开头，整体相似度不足的场景；模型一次重译仍可能复用，QC/人工仍须复核），不改既有 0.75/0.80 阈值。
- P2a 语义审计（ASMR 预设）：在重复/敬称之外，只对五类高置信模式各做一次定点重译——主客方向（`お客様`/私たち/触れ/禁止 且译文写成“我们触碰客人”）、引用归属（`私のことは…って` 被译成“让我叫/我的名字/让你叫”；单独“叫我”不再自动判坏，“他说，叫我雫就好”放行）、凭空第一人称（原文没有私/僕/俺等却出现“我的名字/让我/叫我/用我”）、标签问（原文没有ね/でしょ等却补“对吧/是吧”）、否定疑问（`〜ていませんか/ではありませんか` 译文缺否定标记时）。另在 `finalize` 内做一处窄修复：仅源含 `下の名前で呼んであげて` 且源无第一人称时，把“我的名字/让我/叫我”改成“她的名字/让她/叫她”（`学生 #8`）。重译候选还要通过硬校验、空译/换行/长度、原触发码与重复残余检查；异常保留原译且不写失败，正确候选不会多发请求。示例：`学生 #17` 的“对吧？”会重译为“也就是说要预算”，`治療 #16` 的短候选“禁止客人触碰我们”可被接受。
- T1 确定性守卫（ASMR 主树默认，2026-10-30）：`asmr` 预设自动启用，当前没有 `--no-t1` 开关。额外检测三类高置信问题并各做一次定点重译：短重复（较短源文 ≤8 字却得到同一长译文，拟声/叠词放行）、称谓（`旦那様`/`ご主人様` 被译成“先生/老师”）、臆造道具（译文出现掏耳勺/棉签/梵天等，但原文及前后 ±3 条都没有道具词）。每 cue 最多一次；重译失败/候选被拒保留原译，不记 failure。
- T1 预算与旁路：预算按规模缩放——514 cue 保持 **5 次**整包上限；整包 `max(5, round(总 cue×1%))`，单文件 `max(2, ceil(本文件 cue×1%))`（如 1404 cue → 14；712 cue 文件 → 8，23/51/149 cue 文件仍为 2）。整包次数跨文件共享，单文件次数每文件重置；达到上限后只记 `budget` 事件、不再调用模型。开启 ASMR 翻译时会在输出目录（或唯一输出父目录）旁写 `t1_events.jsonl` 与 `t1_budget.json`，收尾打印“事件 N · 唯一 cue M · 重译 used/max”；这两个文件是审计旁路，不影响 SRT 结构。
- T2 分层模板未默认：C1 `2a1c65e` 只是实验分支（未合入主树、无主树开关、不默认启用）；P4 的 514 盲测因度量不可达结论为 `INVALID_MEASUREMENT_UNREACHABLE`，不作为发布依据，也不产出胜率；不要把它写成“语义收益已证实/已提升”。
- 默认输出文件名插入后缀：`a.srt → a.zh.srt`；`--out-dir` 可指定目录，目录输入的相对层级会一并保留。`--translate-filename` 改为使用译名且**不加 `.zh`**；`--translate-filename-only` 原地改名且不加 `.zh`。
- 滑动上下文：`subtitle` / `asmr` 携带前 12 条原文/译文摘要，`prose` 携带前 10 条，`general` 保持 5 条；每条摘要上限 200 字符。长行/长段达到 token 预算时，引擎会从最老的历史开始裁剪，不会超上下文或 OOM。
- 多文件互不继承滑动上下文：CLI 在每个输入文件前清空历史，避免上一文件的标题、摘要或人名污染下一文件。翻译模板同时约束参考上下文绝缘、第三人称锁定和饮食文化词保真；ASMR 模板禁止裸拟声“咕噜/嗯姆/哧溜/舔”，并把接触音转为动作括号。
- 输出预算：`max(512, 输入 token × 2.5)`，再受档位 `ctx`、系统提示与上下文预算约束；`finish_reason=length` 时自动按句末/中点拆分重译，避免半句静默输出。
- 实况看板：TTY 下在 stderr 局部刷新，头部显示 `[i/N] 文件名 · 已完成/总段数 段 · 百分比 · 本文件已用时间`，下方显示最近 N 段（原文摘要 → 译文摘要 | 耗时 | tok/s）。每行按终端显示宽度裁剪，面板行数不超过终端高度，尺寸变化时先清屏；擦除面板后会回到顶部并清到屏幕末尾，完成行不再被大片空行隔开。非 TTY/管道不绘制动画，但每个文件开始和完成各输出一行。
- 批处理进度：每个文件开始输出 `· [i/N] 正在翻译 文件名`（TTY 下即看板头部），完成后输出 `✓ [i/N] 文件名 → 输出名 · N 段 · 耗时`；有失败段时用 `⚠` 并追加 `N 段失败`，文件级异常用 `✗`，目标已存在时追加 `覆盖`。
- 终态汇总：全部结束后只打印一个报告块，包含文件数、总段数、总汉字、成功/部分失败/失败/中断/覆盖计数、总耗时、平均 tok/s，以及逐文件状态行。默认文件数 ≤12 时列出全部文件，超过 12 个只列异常文件并提示 `-v` 查看全部；失败段明细统一放在报告末尾，每个文件最多列 5 条，超出折叠为 `另有 N 处`。
- 某段失败会保留原文、继续后面的段；文件级异常会跳过该文件并继续后续文件。存在部分失败或失败时返回 `5`，全部成功返回 `0`。`Ctrl+C` 会停止后续文件、保留已完成输出、打印已完成文件的报告并返回 `1`。
- `translate -v` 或 `vanitas -v translate` 显示完整逐文件报告；`--jobs` 只并行解析，请求始终串行（服务端 `-np 1`）。
- ASMR 批量前可运行只读 QC：

```powershell
python scripts\qc_srt.py --source-dir <SRT目录> --zh-dir <SRT目录>
python scripts\qc_srt.py --source-dir <SRT目录> --zh-dir <SRT目录> --json
```

  它按三层检查：繁体/行首标点静默计数；cue 数/序号/时间轴/`[#N]`/不同原文同译文为 error；ASR 疑词、语境“您”、未授权动作括号、译文长度异常、非幻觉空译、假名残留、可疑拉丁词（`SEXPAR`/`Track`/`Warlock` 等）与斜杠并列为 actionable。`duplicate_translation` 先抹平 `ッ`/`ー` 并用 0.60 源文相似阈值，避免拟声词/近义句误报。“您”检查按文档语域判定：服务语域不报、亲密语域必报，中性语域保留原来的单句启发式（`ほら、見て` 仍报）。终端只打印紧凑 `- 原文/+ 译文/? 建议` Diff；`--json` 输出 `summary` 与 `flagged_cues`，`files`/`errors`/`warnings` 保留兼容。error 返回 `1`，仅 actionable 默认返回 `0`，`--strict` 时 actionable 也返回 `1`。

- ASR 跨 cue 断词修复（P2b，翻译前可选）：

```powershell
python scripts\repair_asr_srt.py --source-dir <源SRT目录> --out-dir <独立输出目录>          # 默认 dry-run，只报告
python scripts\repair_asr_srt.py --source-dir <源SRT目录> --out-dir <独立输出目录> --check  # 有待合并返回 1
python scripts\repair_asr_srt.py --source-dir <源SRT目录> --out-dir <独立输出目录> --write  # 真正写盘
```

  规则表默认 `config\asr_joins.tsv`（`left_tail<TAB>right_head<TAB>replacement`，`#` 注释/空行跳过），初始 7 条覆盖 `カ/ウンター`、`手/を`、`寝/込`、`綿/棒`、`心/を`、`気/持ち`、`ホテル/じゃ`。只有左 cue 以 tail 结尾且右 cue 以 head 开头才合并；左前缀为空、时间轴不可解析、`right.start < left.end`、间隔 >1000ms、合并后单条 >8s 都会跳过并在报告里给出原因。合并后 start=左.start、end=右.end，序号重排 1..N；默认不写，`--write` 才输出 `<stem>.srt` 到独立 out-dir。`--out-dir` 不能等于源目录，拒绝输出/输入 `.zh.srt`、目标已存在或同 stem 冲突；坏表/IO/覆盖返回 `2`，`--check` 有待合并返回 `1`，成功返回 `0`。它不原地修改、不产出 `.join.srt`，不替代翻译。

## 7. 批处理

`tasks.jsonl` 每行一个对象：

```json
{"id": "t1", "prompt": "Zero-copy avoids buffer copies.", "task": "translate", "max_tokens": 128}
{"id": "t2", "prompt": "用一句话解释内存映射 I/O。", "max_tokens": 256}
```

- 字段：`id`（可选，默认行号）、`prompt`（必填）、`system`（可选覆盖）、`task`（可选模板名）、`max_tokens`（1–8192）。
- 空行跳过；坏行计为失败但继续执行。
- 结果写 `<input>.out.jsonl`：`{"id","ok","output","error"}`。
- 逐条进度为 `✓ 2/3 t1` 或 `✗ 3/3 t2 失败：缺少 prompt`；收尾打印 `✓ 成功 2 / 共 3 · 结果 tasks.out.jsonl`。
- 任意失败返回 `5`；成功返回 `0`。
- `tasks.jsonl` 的相对路径按启动时的原工作目录解析；输出落在同目录的 `tasks.out.jsonl`。

```bat
vanitas.bat batch tasks.jsonl --model qwen7b
```

## 10. 故障排查

| 现象 | 处置 |
| :--- | :--- |
| `✗ 端口 4060 被 PID … 占用` | 结束占用进程，或 `set VANITAS_PORT=<空闲端口>` 后重试 |
| `✗ 找不到模型文件："…"` | 核对 `config\models.json` 的 `path` 与 `models\` 实际文件名 |
| `✗ 分片缺失 / 启动入口错误` | 7B 两片必须同名同目录；只传首片（`-00001-of-00002`）；不要合并 |
| `✗ 模型体积不足 / 文件不是有效的 GGUF` | 下载未完成或存成了网页/压缩包，重新下载 |
| `✗ 缺少运行组件："…"` | `bin\` 缺 DLL，补齐 llama.cpp CUDA 构建 |
| `⚠ 发现遗留服务，正在清理（PID …）` | 正常行为：守卫回收上次残留实例；反复出现说明上次未正常 `stop` |
| `✗ 旧服务 N 秒内未退出` | 手动结束 `llama-server.exe` 后重试 |
| 启动即退出 | CLI 会打印日志尾部；完整日志在 `~/.vanitas/logs/`（`-v` 可直接看到路径） |
| 显存不足 / 加载中断 | 关闭 GPU 应用；换小模型或降档位；HY 余量最小 |
| `✗ … 返回 HTTP 4xx` | 请求本身不合法，不会重试；看响应体提示 |
| 中文经管道变乱码 | 用 PowerShell 7，或把输入写成 UTF-8 文件后经 `--task`/`batch` 喂入 |
| REPL 没有历史/补全 | `pip install prompt_toolkit`，重启 REPL |
| `✗ 本地命令执行已关闭` | 按 4.3 修改 `settings.json` 的 `tools.exec_enabled` |
| Agent 报“越界操作” | 文件工具目标不在启动时的当前工作目录内；改用工作区内路径，或从目标目录重新启动 `vanitas agent` |
| Agent 报“只允许只读命令” | `run_shell_ro` 不接受 `ren/del/move/copy/mkdir`，也不接受裸 `python <脚本>`；测试改用 `python -m unittest`，文件操作改用 `move_file` / `delete_path` / `write_file` |
| Agent 报“只读 Shell 不允许写操作参数” | 命令里出现 `-exec`、`--output`、`-o`、`-delete` 等；改用只读参数或标准文件工具 |
| `动作 JSON 解析失败：…` | 先检查模型是否输出了 `<tool_call>`/合法 JSON；路径反斜杠会被有限补齐，仍失败时让它改用正斜杠或相对路径 |
| `⚠ 格式解析错误，触发自愈回灌（N/2）` | 模型动作 JSON 不合法；系统自动回灌纠偏，最多 2 次。连续失败会停止，检查模型是否遵守 `<tool_call>` 契约 |
| `⚠ 检测到动作连续/震荡/重复停滞，已触发硬熔断保护` | 模型重复同一动作、A-B 乒乓或短周期循环；换一种描述、先 `list_dir` 或手动确认后再试 |
| `✗ 执行失败：该动作在上一步已失败…` | 相同参数重复提交被阻断；修改参数或换策略，不要继续点 `y` |
| `/undo` 提示没有可回溯的对话 | 历史为空或只有 assistant 消息；先产生一轮 user/assistant 交互 |
| `[... 输出过长已截断：省略中间 ...]` | 正常保护：保留首尾、中间折叠；需要完整内容时让工具缩小输出范围（如指定文件/目录） |
| `Extra data` | 当前解析器用 `raw_decode` + 栈平衡重组多个对象，不再因尾随文本/第二个对象报错；若仍出现，记录原始输出并补单测 |
| 输出没有颜色 | `ui.color` 为 `auto` 时要求 stdout 与 stderr 都是终端；重定向到文件/管道即纯文本。需要强制上色设 `always` |

## 11. 已知限制

- 单实例、`-np 1`：不支持并发请求；吞吐数据均为单流。
- 不做后台队列或无人值守 Agent、Web UI、远程访问、多租户。
- 长上下文质量、持续压测、驱动显存回退策略尚未验证（详见 [项目现状.md](项目现状.md) 第 6 节）。
- 非 UTF-8 输入文件在翻译时会被拒绝并提示转码；`.srt` 仅支持 UTF-8（含 BOM）。
- 自愈回灌与停滞熔断的提示观感、真实终端交互尚未人工验收。
- `tools.max_capture_bytes`（默认 512 KiB）只约束解码后的字符串与反馈；`subprocess.run` 捕获阶段的峰值内存未压测。
- 1000+ 句超长 ASMR 音频的真实 GPU 显存/耗时基准未验收；微批次合流收益以实测为准。
- 实体引擎、静默后处理与新增 Prompt 已在 `自由交谈_梦见庄` 696 条上全量复跑；QC error 0，残余 1 条自造词按 retry 结果手工修正。其余 5 个 SRT 尚未复跑；中文译名变体的一致性仍依赖模型遵循 Prompt，而不是确定性替换。
- ASMR 逐句回退时若模型输出 `[#n]`/多行相邻内容，当前会在 cue 边界清理编号，并把多编号/多行单句回退记失败、保留原文；字幕落盘前仍建议跑 `scripts\qc_srt.py`。
- qwen_coder 的 8K/Q8、16K/Q4、32K/Q4 三档真实显存、OOM 与质量尚未做本机实测；默认 Agent=qwen_coder、chat/batch=qwen7b、translate=hymt，均可由 `settings.defaults` 覆盖。
- `/restart`、`/shutdown` 与 600s 空闲看门狗只通过 mock/单测验证；真实 TTY 下 prompt_toolkit 重绘、休眠提示与唤醒观感未验收。
- 人类 `/exec`/`!` 已完全开放原生 shell；命令风险由用户承担，`AgentTools` 的沙箱边界不变。
