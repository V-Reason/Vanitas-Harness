# Vanitas-Harness 用户使用手册

> 适用版本：`v0.4.0` · 平台：Windows 11 + RTX 4060 Laptop（8 GB）
> 架构与契约见 [总设计方案.md](总设计方案.md)；已知限制与验证边界见 [项目现状.md](项目现状.md)。

---

## 1. 前置条件

| 项 | 要求 | 检查 |
| :--- | :--- | :--- |
| Python | ≥ 3.10 | `python --version` |
| prompt_toolkit | 唯一第三方依赖 | `python -c "import prompt_toolkit; print(prompt_toolkit.__version__)"` |
| llama.cpp | `bin\` 下有 `llama-server.exe`、`llama.dll`、`ggml-base.dll`、`ggml-cuda.dll` | `dir bin` |
| 权重 | 按 `config\models.json` 的路径放入 `models\` | `vanitas models` 会打印路径 |
| 显存 | 空载底噪建议 < 1.5 GiB；HY 需要约 7.7 GiB | `nvidia-smi` |

安装唯一依赖：

```powershell
python -m pip install prompt_toolkit
```

未安装也能运行：REPL 自动降级为 `input()`，失去历史与行编辑，其余功能不变。

## 2. 第一次启动

在仓库根目录（或任意目录调用根目录的 `vanitas.bat`）：

```bat
vanitas.bat
```

首次进入会列出 4 个模型并询问是否启动。选择编号、确认后，CLI 会：

1. 跑守卫（DLL → 模型/分片 → 回收旧实例 → 端口）；
2. 后台启动 `llama-server`，日志写入 `~/.vanitas_logs/`；
3. 轮询 `/health`，就绪后进入提示符 `qwen7b@1 › `。

常用起手式：

```bat
vanitas.bat models                  :: 看模型、端口、档位、别名
vanitas.bat status                  :: 看进程、端口、显存
vanitas.bat serve qwen7b            :: 后台启动并等待就绪
vanitas.bat chat --model minicpm    :: 直接进入 REPL（未启动会自动拉起）
vanitas.bat stop                    :: 结束所有 llama-server
```

`vanitas.bat` 只做三件事：切到仓库根、调用 `python -m vanitas`、透传退出码。因此 `python -m vanitas ...` 与其完全等价。

## 3. 命令速查

| 命令 | 作用 | 示例 |
| :--- | :--- | :--- |
| `vanitas` | 交互式 REPL | `vanitas` |
| `vanitas models` | 列出模型/端口/档位/别名/路径 | `vanitas models` |
| `vanitas status` | 进程、端口、显存、运行记录 | `vanitas status` |
| `vanitas serve <id>` | 启动并等待 `/health` | `vanitas serve hymt --profile 2` |
| `vanitas serve <id> --foreground` | 前台运行，Ctrl-C 退出 | `vanitas serve qwen3b --foreground` |
| `vanitas stop` | 停止所有 `llama-server` | `vanitas stop` |
| `vanitas chat` | REPL；必要时自动启动服务端 | `vanitas chat --model qwen7b --task chat` |
| `vanitas translate <文件...>` | txt/md/srt 批量翻译 | `vanitas translate a.srt b.md --out-dir out` |
| `vanitas batch <tasks.jsonl>` | JSONL 批处理 | `vanitas batch tasks.jsonl --model qwen7b` |
| `vanitas --version` | 版本 | `vanitas --version` |

全局可选 `-v` / `--verbose`（`serve`、`stop`、`status`、`chat` 均可，写在子命令前后都生效）：额外显示 PID、日志路径、监听地址与完整启动参数。默认只显示结论，例如 `✓ 已就绪 · 12.4s`。

退出码：`0` 成功 / `1` 用户中断 / `2` 配置错误 / `3` 守卫失败 / `4` 参数错误 / `5` 引擎或网络失败。

守卫拒绝统一返回 `3`，**退出码是唯一机读契约**；人读消息首行以 `✗` 开头（提示行以 `提示：` 开头），不再带 `[GUARD-CODE=N]` 这类前缀，避免脚本解析消息文本。

## 4. REPL 详解

### 4.1 规则

- 只有「以 `/` 开头且第 2 个字符不是空格」的行是命令；其余整行都发给模型。
- 想提问「/model 是什么意思」时，前面加任意文字即可（如「请问 /model 是什么」）。
- 提示符 `模型@档位 › `（如 `qwen7b@1 › `）；服务端未就绪时仍可用 `/model`、`/status`、`/help` 等本地命令。

### 4.2 命令

| 命令 | 说明 |
| :--- | :--- |
| `/help` | 列出全部命令（由命令表自动生成） |
| `/model` | 列出 4 个模型与运行状态；`*` 标记当前模型 |
| `/model qwen3b` | 切换到已就绪的模型；未就绪时只提示先 `serve`，不会偷偷启动 |
| `/profile` | 查看当前档位与可选档位 |
| `/profile 2` | 设置档位，**只对下次 `serve` 生效** |
| `/system` | 显示当前系统提示 |
| `/system 你只回答一句话` | 设置系统提示文本 |
| `/system prompts\我的提示.md` | 从文件读取系统提示 |
| `/task` | 查看当前任务与可用任务 |
| `/task translate` | 应用 `config\prompts\task_translate.md`，此后每轮输入填入 `{input}` |
| `/clear` | 清空对话，保留系统提示与任务模板 |
| `/save` | 保存到 `~/.vanitas_sessions/<时间>.json` |
| `/save <WORKSPACE>\chat.json` | 保存到指定路径 |
| `/load <WORKSPACE>\chat.json` | 加载会话（恢复模型、档位、系统提示、任务） |
| `/exec dir config` | 在白名单内执行本地命令（默认关闭，见 4.3） |
| `/stop` | 停止服务端，仍留在 REPL |
| `/status` | 模型/档位/端口/运行记录/显存/会话 token 估算 |
| `/quit`（`/exit`） | 退出 REPL；Ctrl-D 等价 |

`/status` 输出样例（`-v` 时额外显示 PID 与日志路径）：

```text
· 模型 qwen7b · Qwen2.5-7B-Instruct Q6_K
· 档位 1 · 4K + Q8_0 KV（近无损，默认） · ctx 4096 · KV q8_0/q8_0
· 端口 4060  ✓ 就绪
· GPU 已用 6834 MiB / 总量 8188 MiB
· 会话 2 条消息 · 约 214 tokens
```

### 4.3 开启 `/exec`

默认 `config\settings.json` 中 `tools.exec_enabled` 为 `false`，任何 `/exec` 都会被拒绝。开启方式：

```json
"tools": {
  "exec_enabled": true,
  "exec_whitelist": ["echo", "dir", "type", "python --version", "git status"],
  "exec_require_confirm": true
}
```

- 白名单按「完整等于或前缀 + 空格」匹配，例如 `git status -s` 命中 `git status`。
- 每次执行都会弹出 `[y/N]` 确认；`exec_require_confirm` 设为 `false` 才会跳过。
- 普通程序不经过 shell，`& | >` 只能作为字面参数；`echo/dir/type` 等 cmd 内置命令走受控 `cmd /c`，并拒绝 `& | < > ^ %`。
- 该功能面向本机排障，不要把它当作沙箱。

### 4.4 上下文与输出

- 预算 = `min(档位 ctx, settings.repl.max_context_tokens) - 512`；超出时从最早一轮丢弃，并打印 `⚠ 上下文已满，丢弃最早 N 轮对话`。
- 回答流式输出；结束后打印 `· token 数 · 耗时 · 首字 · t/s`（token 优先取服务端 `usage`，无则退化为字符数，不会用分片数冒充 token）。
- 代码块以 4 空格缩进显示，围栏标记本身不上屏，便于直接复制。

### 4.5 外观：颜色与符号

默认主题下每条结果都以符号开头：

| 符号 | 含义 | 颜色 |
| :-: | :--- | :--- |
| `✓` | 成功（就绪、已保存、已完成） | 绿 |
| `✗` | 失败（守卫拒绝、引擎错误） | 红 |
| `⚠` | 警告（清理旧实例、上下文裁剪、部分失败） | 黄 |
| `⋯` | 进行中（加载、生成、翻译） | 黄 |
| `·` | 元信息（模型、端口、耗时） | 亮黑（暗） |
| `提示：` | 下一步怎么做 | 亮黑（暗） |

控制方式见 `config\settings.json` 的 `ui` 段：

```json
"ui": {
  "color": "auto",
  "theme": { "prompt": "cyan", "success": "green", "error": "red", "warn": "yellow",
             "info": "cyan", "muted": "bright_black", "accent": "magenta" }
}
```

- `color`：`auto`（默认，stdout 与 stderr 都是终端时上色）/ `always`（强制，含重定向）/ `never`（纯文本）。
- `theme` 的 7 个键必须同时给出；颜色名限 `black…white`、`bright_*`、`default` 共 17 个（见 `vanitas\ui.py`）。
- 整个 `ui` 段可删：缺省时回落内置默认主题，旧配置不需要迁移。
- 颜色经 `ctypes` 打开 Windows 控制台 VT 解析；不支持时自动降级为纯文本，不影响任何功能。

## 5. 模型与档位

| 模型 id | 端口 | 默认档位 | 其他档位 | 场景 |
| :--- | :-: | :--- | :--- | :--- |
| `qwen7b` | 4060 | 4K + Q8_0 | 8K+Q4_0；4K+F16 | 通用主力 |
| `minicpm` | 4061 | 8K + F16 | 32K+F16 | 轻量高质、长文实验 |
| `hymt` | 4062 | 4K + Q8_0 | 8K+Q4_0；4K+F16 | 翻译 |
| `qwen3b` | 4063 | 8K + Q4_0 | 4K+F16 | 回归基线 |

```bat
vanitas.bat serve qwen7b --profile 2          :: 启动 8K + Q4_0
vanitas.bat chat --model minicpm --profile 2  :: 32K 长文
set VANITAS_PORT=4070                          :: 临时换端口
set VANITAS_PROFILE=2                          :: 临时换档位
```

- 一次只运行一个服务端；`serve` 会先回收旧实例（8 GB 显存禁不起双实例）。
- HY-MT2 余量最小（约 500 MiB）；启动前先 `vanitas status`，必要时关闭浏览器、壁纸引擎、Steam。
- 环境变量 `VANITAS_CONFIG_DIR` 可指向另一份配置目录，便于做实验而不污染默认配置。

## 6. 翻译

```bat
vanitas.bat translate docs\readme.en.md
vanitas.bat translate a.srt b.txt --out-dir out\
vanitas.bat translate a.srt --model qwen7b     :: 用通用模型兜底
```

- 支持 `.txt` / `.md` / `.srt`；默认使用 `role=translate` 的模型（`hymt`）。
- `.txt` / `.md`：按空行分段；段内超过 `chunk_chars`（默认 1500）时按句末标点再切；原文空行结构保留。
- `.srt`：只翻字幕文本；序号、时间轴、空行、CRLF/LF、BOM 原样保留；多行字幕整体翻译并保留行结构。
- 输出文件名插入后缀：`a.srt → a.zh.srt`；`--out-dir` 可指定目录。
- 某段失败会保留原文、继续后面的段，最后以 `✗ 某文件 某段：原因` 汇总并返回 `5`；全部成功时打印 `✓ a.srt → a.zh.srt · N 段`。
- `--jobs` 只并行解析，请求始终串行（服务端 `-np 1`）。

## 7. 批处理

`tasks.jsonl` 每行一个对象：

```json
{"id": "t1", "prompt": "Zero-copy avoids buffer copies.", "task": "translate", "max_tokens": 128}
{"id": "t2", "prompt": "用一句话解释内存映射 I/O。", "max_tokens": 256}
```

- 字段：`id`（可选，默认行号）、`prompt`（必填）、`system`（可选覆盖）、`task`（可选模板名）、`max_tokens`（1–8192）。
- 空行跳过；坏行计为失败但继续执行。
- 结果写 `<input>.out.jsonl`：`{"id","ok","output","error"}`。
- 逐条进度为 `✓ 2/3 t1` 或 `✗ 3/3 t2 失败：缺少 prompt`；收尾打印 `✓ 成功 2 / 共 3 · 结果 tasks.out.jsonl`。
- 任意失败返回 `5`；成功返回 `0`。

```bat
vanitas.bat batch tasks.jsonl --model qwen7b
```

## 10. 故障排查

| 现象 | 处置 |
| :--- | :--- |
| `✗ 端口 4060 被 PID … 占用` | 结束占用进程，或 `set VANITAS_PORT=<空闲端口>` 后重试 |
| `✗ 找不到模型文件："…"` | 核对 `config\models.json` 的 `path` 与 `models\` 实际文件名 |
| `✗ 分片缺失 / 启动入口错误` | 7B 两片必须同名同目录；只传首片（`-00001-of-00002`）；不要合并 |
| `✗ 模型体积不足 / 文件不是有效的 GGUF` | 下载未完成或存成了网页/压缩包，重新下载 |
| `✗ 缺少运行组件："…"` | `bin\` 缺 DLL，补齐 llama.cpp CUDA 构建 |
| `⚠ 发现遗留服务，正在清理（PID …）` | 正常行为：守卫回收上次残留实例；反复出现说明上次未正常 `stop` |
| `✗ 旧服务 N 秒内未退出` | 手动结束 `llama-server.exe` 后重试 |
| 启动即退出 | CLI 会打印日志尾部；完整日志在 `~/.vanitas_logs/`（`-v` 可直接看到路径） |
| 显存不足 / 加载中断 | 关闭 GPU 应用；换小模型或降档位；HY 余量最小 |
| `✗ … 返回 HTTP 4xx` | 请求本身不合法，不会重试；看响应体提示 |
| 中文经管道变乱码 | 用 PowerShell 7，或把输入写成 UTF-8 文件后经 `--task`/`batch` 喂入 |
| REPL 没有历史/补全 | `pip install prompt_toolkit`，重启 REPL |
| `✗ 本地命令执行已关闭` | 按 4.3 修改 `settings.json` 的 `tools.exec_enabled` |
| 输出没有颜色 | `ui.color` 为 `auto` 时要求 stdout 与 stderr 都是终端；重定向到文件/管道即纯文本。需要强制上色设 `always` |

## 11. 已知限制

- 单实例、`-np 1`：不支持并发请求；吞吐数据均为单流。
- 不做自动工具循环、Web UI、远程访问、多租户。
- 长上下文质量、持续压测、驱动显存回退策略尚未验证（详见 [项目现状.md](项目现状.md) 第 6 节）。
- 非 UTF-8 输入文件在翻译时会被拒绝并提示转码；`.srt` 仅支持 UTF-8（含 BOM）。
