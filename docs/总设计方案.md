# Vanitas-Harness 总设计方案

> **版本**：`v0.4.1` 后续重构 · **快照**：2026-10-31
> 本文只负责**架构、模块边界、契约与取舍**。当前实测/未验证边界见 [项目现状.md](项目现状.md)，操作步骤见 [用户使用手册.md](用户使用手册.md)，批次过程与旧版全文见 [变更历史.md](变更历史.md)，协作纪律见仓库根 [AGENTS.md](../AGENTS.md)。

## 1. 定位与不可协商约束

单机、单用户、单实例的本地推理套件：把 llama.cpp 的 `llama-server` 包成可配置、可守卫、可交互、可批处理的 CLI。

| 约束 | 决策 | 原因 |
| :--- | :--- | :--- |
| 运行时 | Python ≥ 3.10，主逻辑全 Python | 运维只需一个解释器，Windows 上无需构建 |
| 第三方依赖 | 仅 `prompt_toolkit`（REPL 行编辑/历史） | 依赖面越小，3 个月后越删得掉 |
| 配置驱动 | 模型、端口、上下文、KV 类型只出现在 `config/` | 换模型不改代码，守卫与文档共用同一份事实 |
| 启动入口 | 仓库根 `vanitas.bat`，薄壳：记录原 CWD → 切根 → `python -m vanitas` → 透传退出码 | `.bat` 不承载业务逻辑 |
| 并发 | `-np 1`，一次只跑一个 `llama-server` | 8 GB 显存禁不起双实例；单槽吞吐是已知边界 |
| 工具调用 | 人类 `/exec`/`!` 原生 shell；默认 `vanitas`（等价 `agent`）走受控闭环：单动作/只读数组自动、修改确认、含修改数组一次确认、原 CWD 沙盒、步数受 `settings.agent.max_steps` 控制 | 人类有原生终端特权，模型仍在参数级沙箱内 |
| 明确不做 | Web UI、账号/多租户、远程访问、无人值守 Agent、插件/技能体系、分布式部署 | 当前形态的边界；不放开后台队列或绕过确认 |

## 2. 拓扑与运行链路

```text
vanitas.bat
  └─ python -m vanitas
       └─ cli.main(argv)
            ├─ config.load_config()        读 models.json + settings.json + prompts
            ├─ guard.evaluate()            运行时 → 模型 → 收旧实例 → 端口
            ├─ launcher.start()            Popen(bin/llama-server.exe) + 写 pidfile
            ├─ launcher.wait_ready()       /health + /v1/models 别名校验
            └─ 业务分支
                 ├─ agent.run_agent()      默认入口；受控闭环
                 ├─ repl.run()             vanitas chat 交互对话
                 ├─ translate.translate_file()  批量翻译
                 └─ batch.run_batch()      JSONL 批处理
```

一次 `serve`：加载/校验配置（失败 `2`）→ 守卫按固定顺序检查（失败 `3`）→ `Popen` 启动 → 轮询 `/health`（TTY 显示 `⋯ 正在加载模型 Ns`）→ 校验 `/v1/models` 的 `id` 与 `alias` → 写 `~/.vanitas/run/<id>.json`。退出 REPL 不影响后台服务端，`stop` 负责回收。

依赖方向严格单向：`cli → {config, guard, launcher, client, chat, repl, agent, translate, monitor, batch}`；`chat/repl/translate → client → engine`；`translate/` 内部只允许 `pipeline → {engine, critique} → {window, io, entity, format, cleaner} → types`，`types` 是叶子，`pipeline` 是唯一装配层；`ui`/`metrics` 是最底层叶子。没有反向依赖与循环引用。

## 3. 模块职责

| 模块 | 职责 | 不做什么 |
| :--- | :--- | :--- |
| `cli.py` | argparse 子命令、退出码映射、UTF-8 标准流 | 不拼 llama 参数、不碰业务状态 |
| `config.py`（包） | 读 JSON、严格校验、dataclass 视图、环境变量/偏好覆盖 | 不检查文件是否存在（交给守卫） |
| `guard.py` | 运行时/模型/分片/旧实例/端口检查，退出码 0/1/2/3/4/9 | 不启动服务、不判断显存是否够 |
| `launcher.py` | 进程生命周期、日志、pidfile、`/health` 就绪、停止与状态 | 不决定用哪个模型/档位 |
| `engine.py` | OpenAI 兼容 HTTP、超时、重试退避抖动、SSE、usage/timings 遥测 | 不渲染、不保存历史 |
| `client.py` | `LlamaClient(EngineClient)`：`stream_chat` / `stream_completion` 业务门面 | 不复制传输逻辑 |
| `chat.py` | `ChatRunner`：单轮预算、流式、usage/tok/s、中断与历史 | 不碰命令表、不打印错误 |
| `session.py` | 消息历史、系统提示、任务模板、预算转发、存档、观测折叠 | 不发请求 |
| `render.py` | 纯文本流式渲染、代码块缩进 | 不做 ANSI 全屏重绘 |
| `repl.py`（包） | `/` 命令、Tab 补全、提示符、模型/档位生命周期、`confirm_plan` | 不实现对话协议、不执行 Agent 动作 |
| `agent.py`（包） | `AgentLoop` 显式状态机：解析 → 自愈 → `max_steps` → 停滞熔断 → 审批 → 执行 → `<tool_result>` 回填 → 收尾；`AgentRepl` 只注入钩子 | 不绕过 `tools` 沙盒、不实现后台队列 |
| `metrics.py` | token 估算、聊天/翻译预算、汉字计数、耗时/速率、SegmentStat | 不做 I/O |
| `prompts.py` | 模板加载、占位符校验/替换、秒级 `{date}`、`{cwd}` | 不拼请求体 |
| `tools.py`（包） | 人类 `/exec` 原生 shell；`AgentTools` 强类型文件工具、只读 Shell、`is_inside_workspace`、512 KiB 字节折叠 | 人类执行与模型工具彻底分离，不做后台任务/自动重试 |
| `translate/` | txt/md/srt 分段、目录展开、输出规划、翻译、重组、上下文/预算/清洗、cue 后处理、实体倒排、失败汇总；对外仍是单一模块 | 不管理服务端、不画终端 UI |
| `translate/pipeline.py` | `translate_file`/`translate_srt`/`translate_prose` 串联：语域、实体、合流、局部回退、P3 复审挂载、`.part.srt` 快照/`--resume`、审计重译、T1 预算 | 不实现清洗/解析/路径规则 |
| `translate/engine.py` | `TranslationEngine`：滑动上下文、预算门禁、截断二分重译、流式早停、文件名翻译、`critique` 通道 | 不认识 SRT/cue、不做审计 |
| `translate/critique.py` | P3 定向复审：`triage_cue_risk` 分流、`CritiqueBudget` 双层熔断、`execute_critique_repair` 隔离调用 | 不写回、不写滑动上下文、不 import pipeline |
| `monitor.py` / `batch.py` | 翻译看板/汇总；JSONL 逐行执行与结果落盘 | 不依赖 translate 业务逻辑；不重试失败行 |
| `ui.py` / `progress.py` | 颜色名→ANSI、符号前缀、VT 开关、TTY 覆盖式进度 | 不 import 业务模块、不 `print` |

## 4. 配置契约

### 4.1 `config/models.json`

字段名固定；新增模型只允许追加 `models[]` 条目，不得改 schema。关键字段：`id`（CLI 短名，唯一）、`display`、`path`（分片指向 `-00001-of-0000N` 首片）、`port`（唯一）、`alias`（`-a` 与 `/v1/models` 的 id）、`shards`、`role`（`general`/`light`/`translate`/`baseline`）、`template_kwargs`、`profiles`（键为数字串，每档 `ctx/kv_k/kv_v/desc`）、`default_profile`、可选 `repeat_penalty`。

校验失败一律 `ConfigError` → 退出码 `2`：`version == 1`；id/port/alias 唯一；档位键为数字串且默认档位存在；KV 在 `f32/f16/bf16/q8_0/q4_0/q4_1/q5_0/q5_1/iq4_nl` 内；分片命名与 `shards` 自洽；`path` 解析为绝对路径；`repeat_penalty >= 1.0`；未知字段直接报错。

优先级：`--profile` > `VANITAS_PROFILE` > `default_profile`；端口 `VANITAS_PORT` > `models[].port`；配置目录 `--config-dir` > `VANITAS_CONFIG_DIR` > `<仓库根>/config`。

### 4.2 `config/settings.json`

可调运行参数全部收口于此，业务模块只消费 `AppConfig.settings`。段与语义：

| 段 | 关键字段 | 语义 |
| :--- | :--- | :--- |
| `defaults` | `agent/chat/translate/batch` | 各模式默认模型 id；缺省回落 role；`serve` 仍须显式模型 |
| `request` | `timeout_sec/max_retries/backoff_*/health_timeout_sec` | HTTP 超时、重试退避、健康检查 |
| `launcher` | `health_timeout_sec/health_poll_interval_ms/kill_wait_sec/log_tail_lines` | 就绪等待、停止等待、失败日志尾行 |
| `repl` | `max_context_tokens/context_reserve_tokens/min_output_tokens/idle_timeout_sec/context_collapse_*/ctx_*` | 历史与输出预算、空闲休眠、观测折叠、状态条阈值 |
| `chat` | `temperature` | 对话/Agent 采样温度 |
| `agent` | `max_steps/max_batch_actions/max_feedback_chars/max_parse_retries/stagnation_limit/feedback_*_lines` + 审批集合 | 步数、批量、反馈上限、自愈次数、熔断阈值、头尾行数、动作审批 |
| `tools` | `exec_enabled/exec_require_confirm` + 文件/Shell 策略 | 人类 `/exec` 开关；`readonly_shell_prefixes`/`project_prefixes`、文件限制、写参数黑名单只约束 AgentTools；`max_capture_bytes` 默认 512 KiB |
| `translate` | 源后缀、chunk、输出后缀、上下文、预算、`default_preset`、`environment`、`strip_trailing_periods`、`presets` | 预设含 `task_template/window_size/max_window_chars`；`presets` 可覆盖 profile/context/chunk |
| `ui` | `color` + 7 键主题 | `auto/always/never`；整段可缺省，缺省回落默认 |

`ui.theme` 的 7 个键（`prompt/success/error/warn/info/muted/accent`）必须同时给出，颜色名限 17 个；`config` 与 `ui.py` 各存一份 `COLOR_NAMES` 并由单测锁定一致，避免循环依赖。`/exec` 子进程超时复用 `request.timeout_sec`，不另设字段。

### 4.3 `config/prompts/`

只认 `{input}`、`{context}`、`{context_history}`、`{date}`、`{model}`、`{cwd}` 六个占位符。`task_*.md` 必须含 `{input}`；未知占位符、空模板、路径穿越（`../`、大写名）在启动前报错。`{date}` 为秒级本地时间；`{cwd}` 由 `Session.build_user_message` 注入，优先 `VANITAS_ORIG_CWD`，其次显式参数，最后进程 CWD；`task_translate.md` 用 `{context_history}`；`system_default.md` 为默认系统提示；`/system`、`/task` 可在会话内覆盖。

格式按模型选择：`task_chat`/`task_code`/`task_agent`/`task_translate_asmr` 用 XML 风格分节；`task_translate` 与 `agent_continue` 保持紧凑纯文本；`system_default` 全静态。ASMR 生产模板当前为 V4（`12,427 B / A5E05880`），分节为 `<language_and_voice>`/`<sensory_immersion>`/`<asmr_domain_lexicon>`/`<asr_repair_protocol>`/`<sfx_and_staging_rules>`/`<counting_and_io_guardrails>`/`<contrastive_examples>`/`<io_contract>`；运行时变量统一位于静态规则之后，`{input}` 最后。V4 精简掉的条款、覆盖损失与实测见变更历史 §52，不得在未同步测试的情况下改模板字节。

## 5. 进程、端口与守卫

| 模型 | 端口 | 默认档位 | 用途 |
| :--- | :-: | :--- | :--- |
| `qwen_coder` | 4060 | 8K + Q8_0 | Agent 默认主力 |
| `qwen7b` | 4063 | 4K + Q8_0 | chat/batch 默认；通用后备 |
| `minicpm` | 4061 | 8K + F16 | 轻量 |
| `hymt` | 4062 | 4K + Q8_0 | 翻译；预设固定 profile 2 |

启动参数逐字固定：

```text
llama-server.exe -m <path> --host <host> --port <port> -c <ctx> -ngl 999 -np 1
                 -fa on -ctk <kv_k> -ctv <kv_v> -a <alias> -fit off --metrics
```

`-fa on`、`-fit off`、`-np 1`、`-a`、`--metrics`、分片只传首片都是硬语义，不得在重构中“顺手优化”。不得复用 8080 段；单实例：启动新模型前由守卫回收所有 `llama-server.exe`。

守卫顺序固定：**运行时（4 个 DLL）→ 模型（存在/分片/体积/GGUF magic）→ 回收旧实例 → 端口**。先验模型再杀旧实例，避免目标不可用时误伤正在服务的实例；端口仍被占则报 PID 与映像名。

| 退出码 | 含义 | 人读首行 |
| :-: | :--- | :--- |
| 0 | 通过 | `✓ 环境核验通过 · …` |
| 1 | 端口被占 | `✗ 端口 <port> 被 PID <pid> (<name>) 占用` + `· 设置 VANITAS_PORT=<空闲端口>` |
| 2 | 模型缺失/分片不全/非法 | `✗ 找不到模型文件…` / `✗ 分片缺失…` / `✗ 模型体积不足…` |
| 3 | 运行时缺失 | `✗ 缺少运行组件："…"` + `· 请将 llama.cpp CUDA 包完整解压到 bin\ 目录` |
| 4 | 旧实例未退出 | `✗ 旧服务 <n> 秒内未退出…` |
| 9 | 参数错误 | `✗ 端口必须是整数…` / `✗ 缺少模型路径` |

**退出码是唯一机读契约，消息只负责人读**：不加 `[GUARD-CODE=N]` 前缀，也不加 `[GUARD]`/`[GUARD-FATAL]` 标签。`GuardResult` 只存未着色纯文本；`format_for_cli(result, palette)` 仅按首符号上色，失败路径由 CLI/REPL 统一打印一次。

## 6. 客户端与流式

- 只用 `/v1/chat/completions`、`/v1/models`、`/health`；`urllib` 全部走 `ProxyHandler({})`，避免系统代理劫持 `127.0.0.1`。
- 超时：连接与读分别可控，默认 `request.timeout_sec`；健康检查固定短超时、不重试。
- 重试矩阵：连接错误/超时/5xx 重试；4xx 与协议错误不重试（`EngineError.retryable=False`）。退避 `base * 2^i + U(0, jitter)`，上限由 `max_retries` 控制。
- 流式逐行解析 `data:`，`[DONE]` 收尾；记录 TTFT、tokens、耗时、`usage`、`timings`、`finish_reason`。首字前失败可重试，已输出后不重试；`on_progress` 约 200ms 节流。
- 请求体固定注入 `chat_template_kwargs`（空对象不注入）；`enable_thinking=false` 对 MiniCPM5 是必需项；`repeat_penalty > 1.0` 时注入同名采样字段。
- 指标口径：吞吐优先 `timings.predicted_per_second`，其次 `usage.completion_tokens / elapsed`；SSE 分片数不是 token，禁止拿来算 t/s。
- `client.py::LlamaClient` 是业务门面（`stream_chat`/`stream_completion`），`engine.py` 是唯一传输层，避免双份 HTTP 实现。

## 7. 交互与 Agent

无子命令时 `HANDLERS[None]` 直接分派 `_cmd_agent`，因此 `vanitas` 与 `vanitas agent` 等价；`vanitas chat` 才进入纯 REPL。只有“以 `/` 开头且第 2 个字符不是空格”的行是命令，其余整行都是用户输入。

- 命令面：`/help`、`/model [id]`、`/profile [N]`、`/restart`（`/reload`）、`/system [text|file]`、`/task [name]`、`/clear`、`/undo`（`/pop`/`/rollback`）、`/save`、`/load`、`/exec`/`!cmd`、`/stop`（`/kill`）、`/shutdown`（`/halt`、`/exit all`）、`/status`、`/quit`（`/exit`）。
- 提示符 `<id>@<档位> [ctx: N%] › `（Agent 默认 `qwen_coder@1`，chat 默认 `qwen7b@1`）；60% 黄、80% 红；休眠态追加 `[休眠]`；TTY 且有 `prompt_toolkit` 时启用历史、行编辑与 Tab 补全，否则降级 `input()`；非 TTY 提示符写 stderr，stdout 只留回答。
- 档位：`self.profile` 只代表当前服务端实际档位；`/profile N` 写入待生效档位与 `~/.vanitas/preferences.json`，`/restart` 才热重启。偏好优先级 `--profile` > `VANITAS_PROFILE` > `preferred_profiles[model]` > `models.json::default_profile`；损坏/失效回落默认，不阻断启动。
- 生命周期：`IdleWatchdog` 单守护线程每 10s 检查；空闲 600s 且有服务时，脏会话先原子写 `~/.vanitas/sessions/autosave.json`，再 `stop_all()` 并置休眠；下一次输入自动唤醒。`/restart` 与 `/shutdown` 通过状态锁与看门狗 pause/resume 避免竞争。
- 上下文：`budget = max(256, min(档位 ctx, repl.max_context_tokens) - repl.context_reserve_tokens)`；超预算从最早用户/助手对开始丢，不实现自动摘要。超 `context_collapse_ratio`（默认 0.65）时，把早于最近 `keep_rounds`（默认 2）轮、长度 ≥1000 的旧 `<tool_result>` 折叠为锚点；动作签名与最近两轮不折叠。
- 单轮输出预算 `max(repl.min_output_tokens, 档位 ctx - 历史 tokens - repl.context_reserve_tokens)`；`ChatRunner` 统一计算。渲染增量写 stdout 并 flush；代码围栏内 4 空格缩进；结束后打印 `· token 数 · 耗时 · t/s`，`-v` 追加首字，`finish_reason=length` 追加截断警告。
- Agent 默认 `task_agent`，模型优先输出 `<tool_call>[...]</tool_call>`，同时兼容裸单动作对象/数组；`extract_tool_calls` 优先标签，失败后用 `JSONDecoder.raw_decode()` 与栈平衡扫描恢复多对象/尾部垃圾，并对路径字段的未转义 Windows 反斜杠做有限修复。
- `AgentLoop` 状态机：解析 → 自愈回灌（≤2 次）→ 无动作收尾 → `max_steps` → 停滞检测 → 本轮同参数失败 → 确认/自动执行 → `<tool_result>` 回填 → 下一轮。解析成功即清零自愈计数；`AgentRepl` 只注入 `converse/confirm/announce/execute/finalize` 五个钩子。
- 审批：单动作与只读数组自动执行；`write_file`/`patch_file`/`delete_file`/`delete_path`/`move_file` 必须确认；含修改的数组打印编号清单并只弹一次 `[y/N]`；`/exec` 仍手动逐次确认。用户拒绝不执行，越界转失败反馈。
- 停滞签名是 `(action.name, json.dumps(parameters, sort_keys=True))`；覆盖连续 3 次、A-B-A-B 第 4 步、A-B-C-A-B-C 第 6 步、最近 6 步同签名 ≥3 次，以及批次级重复/乒乓；命中即硬熔断且本次不执行。失败签名本轮内持久保留，中间穿插只读动作也不清空；同参数再提交不弹确认、直接回填“此前已失败”。
- `max_steps` 计执行步与失败阻断步；反馈用 `_clip_feedback` 保留前 20 行/后 40 行（字符分支 30%/70%），中间标记含「已截断」。`/undo` 从末尾持续弹出直到真正的人类 user，清理最近动作窗口与失败集合，下一提示符按新百分比渲染。

## 8. 翻译契约

- `.txt`/`.md`：按空行分段，段内超 `chunk_chars` 优先句末标点切，其次空格，最后硬切；段落前后空白原样保留，段间空行数量不变。
- `.srt`：按空行分块，校验“序号 + 时间轴”；只翻字幕文本，多行字幕整体一次请求并保留行结构；重排序号、时间轴、空行与换行风格，检测到 BOM 则写回 BOM。`parse_srt` 用 `splitlines()` 兼容 CRLF/LF/CR，`rebuild_srt` 统一目标 EOL。
- 微批次合流：`translate_srt` 接受 `window_size`（默认 1）与 `max_window_chars`（默认 250）；窗口内拼 `[#序号] 台词`。`parse_window_response` 校验缺失、多翻、重复与乱序；`align_window_response` 判三态（完全对齐/缺项可用/灾难），`identify_suspicious_cues` 逐 cue 定位；只重译损坏项，结构灾难或损坏项 ≥ 半数才整窗回退，禁止对 `1..M` 残缺前缀做位置猜测。
- 批次响应必须保留 `[#N]`：`sanitize_translation_output` 不再全局删除编号，编号只在 cue 边界由 `strip_window_id_prefix`/`postprocess_cue_text` 清理。模型每窗从 `[#1]` 重编号时，仅在编号为 `1..K` 且数量一致时按位置恢复。
- ASMR 预设：`--preset asmr` 选 `task_translate_asmr.md`，`window_size=6`、`max_window_chars=250`；模板覆盖 ASR 片尾幻觉/循环套话清洗、音近错词推演、口吃保留、拟声词转译、全角动作括号与 `[#序号]` 契约。V4 的覆盖损失见变更历史 §52，不要凭旧版记忆补条款。
- ASR 硬清洗：命中 `ご視聴ありがとうございました`、`チャンネル登録`、`高評価`、`ベルマーク`、`Thank you for watching`、`Please subscribe`、`Sous-titres` 的块置空、不耗 token、保留序号/时间轴；空正文写回不追加末尾换行。
- 文档级实体：`window_size>1` 时构建 `DynamicEntityEngine`，只以敬称名、`という名`/`役` 明确姓名与“3–4 字汉字块共同前缀”为种子；裸片假名/拟声词/普通名词不建实体，停用表拦截 `トラック`/`セックス`/`バイバイ`/`コショコショ` 等。`capture_translations` 只保存洁净示例，`_extract_locked_name` 只锁高置信裸名，`enforce_locks` 只替换未翻译日文专名；`enforce_locks` 用单遍正则交替 + 已锁定名哨兵遮蔽，防止逐变体替换级联成「梅地先生先生」。
- 后处理链：`postprocess_cue_text → enforce_locks → glossary.apply → apply_pronoun_policy → repair_first_person_name → repair_quote_private → validate_cue_translation`。`postprocess_cue_text` 做简繁、行首标点、重复句号、未授权动作括号、连续空行折叠与乱码替换符剥离；`validate_cue_translation` 拒绝空行、假名、`SEXPAR`/`Track`、中日文斜杠与乱码替换符。
- 写回失败兜底：批次失败整窗回退；单句失败按“失败原因回灌重译一次 → 仍不合格填回候选 → 无候选（引擎异常）才留原文”三级处理，均记 failure。`salvage_slash_translation` 优先唯一中文项、否则取第一个非空项，避免把整句日文源写回。
- 质量审计：`quality.py`（纯标准库，不 import `vanitas.translate`）提供术语表、文档语域、`您→你` 策略、文档级重复索引与窄规则审计。`DuplicateIndex` 用精确哈希 + 3-gram 倒排；源文相似 ≥0.75 视为合法重复，译文 ≥12 字才判定；候选按共享 trigram 降序、同分按 cue 序号，只比较前 32 个。审计命中每 cue 最多一次定点重译，前后用 `history_snapshot`/`restore_history` 隔离；重译仍不合格保留原译，不写 `failures`。
- 语义审计顺序：`duplicate → short_duplicate → customer_direction → quote_private → negative_question → first_person → tag_question → address_term → invented_name → invented_tool → under_translation → honorific`；`combine_hints` 去重取前 2 条。五类窄规则全部 AND 触发、空源/空译放行；`quote_private` 的坏模式收窄为 `让我叫|我的名字|让你叫`，单独“叫我”不自动判坏。
- T1 确定性闭集：`ASMR_T1_CODES = {short_duplicate, address_term, invented_tool, invented_name, under_translation}`，只在 `asmr_guard=True` 时参与，只报 issue，由 `audit_retry()` 做一次定点重译。`short_duplicate` 的较短源文上限为 11 字（`SHORT_DUPLICATE_MAX_SOURCE_CHARS`），拟声/叠词放行；`under_translation` 只判“源文 ≥10 字、译文 ≤2 字”，**刻意不做比例判定**；`invented_name` 只登记提示词示例专名，不做开放集人名检测。
- T1 预算：`T1Budget.for_corpus = max(5, round(total_cues*1%))`，`begin_file.per_file = max(2, ceil(file_cues*1%))`；`total` 跨文件共享、`file_total` 每文件重置。预算不足只记 `budget` 事件，不再调用模型。ASMR 由 `prompts.is_asmr_task()` 自动开启，没有 `--no-t1`。
- 滑动上下文：`TranslationEngine` 维护 `deque(maxlen=context_window)` 的 `(原文, 译文)`；首段填“无前文，故事开端”。合流不再调用 `record_window_history()`，每窗在审计/重译后 `restore_history(批前快照 + 已接受 cue)`，`context_window=12` 是 12 条 cue 而不是 72 条；批次接受前用 `_copies_history()` 查跨窗复制，命中整窗回退。
- 输出预算：`desired = max(translate.min_output_tokens, input_tokens * translate.output_ratio)`，再被 `n_ctx - prompt - safety` 截断；`finish_reason=length` 时按句末/中点二分递归重译（最多 `max_split_depth` 层，默认 3），仍失败才记失败并保留原文。
- 目录/文件名：目录输入由 `collect_translate_inputs()` 启动模型前递归展开，只收 `source_suffixes`，按真实路径去重，跳过已有产物并剪掉 `--out-dir`；输出规划保留相对层级、拒绝目标冲突/覆盖输入。`--translate-filename` 翻译内容+文件名并覆盖 `output_suffix` 为空串；`--translate-filename-only` 只原地改名、支持任意扩展名、拒绝 `--out-dir`。
- 过程文件：`translation_meta.json`/`t1_events.jsonl`/`t1_budget.json` 统一写到 `~/.vanitas/translate/<时间戳>/`，输出目录只留译文；`.part.srt` 仍在输出目录，成功即删、中断期间作为续传锚点。
- 质量检查（QC v2）：判定是纯函数模块 `vanitas/qc.py`（只复用 `translate.cleaner`/`translate.format`/`quality` 的公开接口，不 import 私有实现），`scripts/qc_srt.py` 只做参数、遍历、渲染与退出码。severity 三档 `block`/`review`/`info` 各有操作含义，`level` 保留旧值做兼容。**不变量优先**：结构四件套与 `garbled`（U+FFFD）是 block；`pipeline_drift`（当前后处理的不动点比例）与 `glossary_forbidden`（术语表收敛态）直接调用生产函数，阈值自由度为零。**定义类**直接调用 `quality.audit_*`（`invented_name`/`under_translation`/`invented_tool`/`address_term`/`short_duplicate`）或 `quality.detect_organ_swap`（`organ_mismatch`，与生产端修复共用同一 guard，避免“检测一套、修复一套”），重复检测改用 `DuplicateIndex`，删除了自建 similarity 与 O(n²) 扫描；`pronoun_mixed` 是语域层的文件级判定（锚定首个切换 cue），与生产端 `detect_register`+`apply_pronoun_policy` 同一口径。**标定**：`tests/data/qc_golden.tsv` + `tests/benchmarks/bench_qc.py` 给出 per-code P/R，block 要求 P=1.00、review 要求 P≥0.85 且 R≥0.60；这些数字只在该标定集上成立，不是全语料结论。历史口径与取舍见 `docs/变更历史.md` §57。

## 9. 工具执行安全模型

- 人类 `/exec`/`!cmd`：`exec_enabled` 总开关与 `exec_require_confirm` 保留；命令以原生 `shell=True` 交给系统 shell，不再匹配 `manual_exec_prefixes`、不再做目录/破坏性路径拦截，支持管道与重定向。工作目录优先 `VANITAS_ORIG_CWD`；超时复用 `request.timeout_sec`，stdout/stderr 各做 512 KiB 字节折叠。
- Agent 工具与人类 `/exec` 完全分离：前者继续走只读白名单、`is_inside_workspace` 与写参数黑名单；后者的开放不降低 `AgentTools` 沙箱边界。
- Agent 工具：`read_file`、`read_file_range`、`grep_workspace`、`patch_file`、`write_file`、`move_file`、`delete_path`（`delete_file` 兼容）、`list_dir`，全部先过 `is_inside_workspace`。`delete_path` 对文件 `unlink`、目录 `rmtree`、符号链接只删链接本身，工作区根与父级硬拒绝。
- 路径约束：`Path.resolve()` 跟随符号链接，再用 `os.path.commonpath` + `normcase` 判断是否在根内；空串、NUL、不同盘符、父目录、绝对越界路径一律拒绝，抛 `ToolDenied`。`raise_on_error=False` 仅用于查询。
- 强类型契约：`read_file` 只接受 UTF-8，大小上限 `max_read_bytes`；`write_file` 只接受 `str`；`patch_file` 要求 `search` 唯一命中并保留原 BOM，只改内容、不改文件名；重命名/改扩展名必须 `move_file(src,dst)`；`read_file_range` 1-based 闭区间、`end` 超 EOF 夹取、`start` 超 EOF 拒绝、跨度受 `max_range_lines` 限制；`grep_workspace` 受 `max_grep_results`/`max_grep_file_bytes` 限制；`list_dir` 条数上限 `max_list_entries`。
- Agent 只读 Shell 前缀来自 `settings.tools.readonly_shell_prefixes`（默认 `dir/ls/type/cat/echo/findstr/find`、`git status/log/diff/show/rev-parse`、`python -m unittest` 等）；`python verify.py` 只允许出现在 `project_prefixes`。`-exec`、`--output`、`-o`、`-delete`、`-fprint` 等写参数由 `readonly_blocked_flags`/`readonly_blocked_prefixes` 拦截；`dir/type/echo` 由 Python 只读实现，其余 `shell=False`。
- 修改类 shell 命令（`ren/rename/move/del/erase/copy/mkdir` 等）不在 Agent 白名单内；提示词要求模型改用 `move_file/delete_file/write_file`。Git 禁止 `-C`、`--git-dir`、`--work-tree`、`--no-index` 等路径改写选项，并关闭 pager 与可选锁。
- 子进程输出按 UTF-8 → 本地代码页 → `mbcs` 顺序解码；`_execute` 在解码前对 stdout/stderr 各做 512 KiB 折叠（前 1/4 + 后 3/4，插 `[stdout truncated]`）。捕获仍由 `subprocess.run` 完成，该折叠只限制解码/反馈体积，不限制捕获峰值。

## 10. 取舍、明确不做与历史指针

- **为什么 Python 而不是继续堆 bat**：守卫逻辑（分片、netstat、tasklist、JSON）在 bat 里已到可维护性极限；Python 可用标准库表达且可单测。
- **为什么保留 0/1/2/3/4/9 守卫退出码**：已有脚本与验收基准依赖它；CLI 透传为 `3`，消息只负责人读。
- **为什么颜色用原生 ANSI + ctypes 开 VT**：`rich`/`colorama` 会让依赖面翻倍；`ui.py` 是唯一渲染细节入口。
- **为什么端口 4060 段**：8080 段长期被桌面进程占用；4060 与显卡型号一致，便于记忆。
- **为什么单实例**：显存余量决定不能并行；单实例也让 `stop`、`status`、pidfile 语义简单。
- **为什么确认分级**：单轮规划无法完成改名、读取、写入等多步任务；但每一步都确认会让只读勘察和批量改名不可用。闭环改为“单动作与只读数组自动、修改动作确认、含修改数组一次确认”，仍保留 CWD 沙盒与 `max_steps` 上限。
- **为什么文档分开**：架构契约 / 当前事实 / 操作步骤 / 历史 / 协作规范各自单一职责，避免一份巨型文档同时承担四种角色。
- **为什么实验失败也保留记录**：T2/C1 不默认、P3 定向复审默认关闭、V6 后文参考默认关闭、V4 的覆盖损失与 S2/V1 的否决方案都留在变更历史，防止下次“顺手加回”。
- **已否决/明确不做**：不做 Web UI、多租户、远程访问、后台队列/无人值守 Agent、插件体系、分布式部署；不做自动摘要；不做“译文/源文比例”漏译判定；不做开放集人名检测；不允许用 `patch_file` 改文件名；experimental 失败不 fallback 生产模板；不把单测通过写成端到端通过。
- **历史指针**：v0.4.1/批次 1–8、Agent/工具/路径/配置见 §8–§25；翻译预设/提示词/目录/文件名/ASMR 词典见 §26–§35；ASMR 守卫/P1/P2a/P2b/V5/V6/E0/T1/环境隔离见 §36–§43；拆包/P2–P6/80-cue/主动防御/V4/S2-V1 见 §44–§53。详情与旧版全文见 [变更历史.md](变更历史.md)。
