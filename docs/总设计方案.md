> 版本：`v0.4.1` · 快照：2026-10-26

## 1. 定位与不可协商约束

单机、单用户、单实例的本地推理套件：把 llama.cpp 的 `llama-server` 包成可配置、可守卫、可交互、可批处理的 CLI。

| 约束 | 决策 | 原因 |
| :--- | :--- | :--- |
| 运行时 | Python ≥ 3.10，主逻辑全 Python | 运维只需一个解释器，Windows 上无需构建 |
| 第三方依赖 | 仅 `prompt_toolkit`（REPL 行编辑/历史），其余标准库 | 依赖面越小，3 个月后越删得掉 |
| 配置驱动 | 模型、端口、上下文、KV 类型只出现在 `config\` | 换模型不改代码，守卫与文档共用同一份事实 |
| 启动入口 | 仓库根 `vanitas.bat`，6 行薄壳（4 条核心指令） | `.bat` 不承载业务逻辑，跨终端行为一致 |
| 并发 | `-np 1`，一次只跑一个 `llama-server` | 8 GB 显存禁不起双实例；单槽吞吐是已知边界 |
| 工具调用 | 人类 `/exec`/`!` 原生 shell；默认 `vanitas`（等价 `agent`）受控闭环：单动作/只读数组自动、修改确认、含修改的数组一次确认、原 CWD 沙盒、步数由 `settings.agent.max_steps` 控制 | 人类拥有原生终端特权，模型仍在参数级沙箱内 |
| 明确不做 | Web UI、账号/多租户、远程访问、无人值守 Agent、插件/技能体系、分布式部署 | 当前形态的边界：本次只放开受控闭环，不放开后台队列或绕过确认 |

## 2. 物理拓扑

```text
Vanitas-Harness\
├── vanitas.bat                 # 唯一入口：记录原 CWD → cd 根目录 → python -m vanitas %*
├── AGENTS.md                   # 开发范式与协作红线
├── README.md                   # 一页索引
├── bin\                        # llama.cpp CUDA 构建（不入库）
├── models\                     # GGUF 权重（不入库；7B 为 2 分片）
├── config\
│   ├── models.json             # 模型/端口/别名/分片/档位
│   ├── settings.json           # 超时/重试/启动/REPL/工具/翻译
│   └── prompts\                # system_default + task_{chat,translate,code,agent}.md
├── vanitas\                    # CLI 实现
├── tests\                      # 单元测试 + 验收基准 + 运行产物（reports/ 不入库）
└── docs\                       # 本文件、现状、使用手册、范式笔记
```

`bin\`、`models\` 是只读输入：任何流程都不得改名、合并、改写权重或 DLL。运行产物写到用户目录（`~/.vanitas/logs/`、`~/.vanitas/run/`、`~/.vanitas/sessions/`、`~/.vanitas/history`），不污染仓库。

## 3. 运行链路

```text
vanitas.bat
  └─ python -m vanitas
       └─ cli.main(argv)
            ├─ config.load_config()        读 models.json + settings.json + prompts
            ├─ guard.evaluate()            运行时 → 模型 → 收旧实例 → 端口
            ├─ launcher.start()            Popen(bin/llama-server.exe) + 写 pidfile
            ├─ launcher.wait_ready()       /health + /v1/models 别名校验
            └─ 业务分支
                 ├─ agent.run_agent()      默认入口（无子命令）；受控闭环
                 ├─ repl.run()             vanitas chat 交互对话
                 ├─ translate.translate_file()  批量翻译
                 └─ batch.run_batch()      JSONL 批处理
```

一次 `serve` 的时序：

1. 加载并校验配置（失败 → `2`）。
2. 守卫按固定顺序检查（失败 → `3`，stderr 首行以 `✗` 开头，提示行以 `·` 开头）。
3. `subprocess.Popen` 启动 `llama-server.exe`，参数由配置拼装、逐字固定（见 6.2）。
4. 轮询 `/health` 至 `status == "ok"`（TTY 显示 `⋯ 正在加载模型 Ns` 覆盖行，非 TTY 静默）；进程提前退出则带日志尾部报错。
5. 校验 `/v1/models` 返回的 `id` 与配置 `alias` 一致，防止端口上跑着别的模型。
6. 写 `~/.vanitas/run/<model_id>.json`，返回端点；退出 REPL 不影响后台服务端，`stop` 负责回收。

依赖方向严格单向：`cli → {config, guard, launcher, client, chat, repl, agent, translate, monitor, batch}`；`chat/repl/translate → client → engine`；`repl → {config, launcher, prompts, session, tools, guard, ui}`；`agent → {repl, chat, tools, render, ui}`；`launcher → {guard, engine, config}`；`translate/ → {client, config, errors, metrics, prompts, quality, cue_boundary}`；`monitor → {metrics, ui}`（不依赖 translate）；`engine/guard → {config, errors}`。`translate/` 子包内部只允许向下：`pipeline → {engine, critique} → {window, io, entity, format, cleaner} → types`（`critique → {types, cleaner, quality}`，且**不 import pipeline**，`finalize`/`candidate_ok` 以可调用参数注入）；`types` 是子包叶子，`pipeline` 是唯一装配层。`ui`/`metrics` 是最底层叶子；没有反向依赖与循环引用。

## 4. 模块职责

| 模块 | 职责 | 不做什么 |
| :--- | :--- | :--- |
| `cli.py` | argparse 子命令、退出码映射、UTF-8 标准流 | 不拼 llama 参数、不碰业务状态 |
| `config.py` | 读 JSON、严格校验、dataclass 视图、环境变量覆盖 | 不检查文件是否存在（交给守卫） |
| `guard.py` | 运行时/模型/分片/旧实例/端口检查，退出码 0/1/2/3/4/9 | 不启动服务、不判断显存是否够 |
| `launcher.py` | 进程生命周期、日志、pidfile、`/health` 就绪、停止与状态 | 不决定用哪个模型/档位 |
| `engine.py` | OpenAI 兼容 HTTP、超时、重试退避抖动、SSE、usage/timings 遥测 | 不渲染、不保存历史 |
| `client.py` | `LlamaClient(EngineClient)`：`stream_chat` / `stream_completion` 业务门面 | 不复制传输逻辑 |
| `chat.py` | `ChatRunner`：单轮预算、流式、usage/tok/s、中断与历史；支持 Agent 静默输出与反馈续轮 | 不碰命令表、不打印错误 |
| `session.py` | 消息历史、系统提示、任务模板、预算转发、存档 | 不发请求 |
| `render.py` | 纯文本流式渲染、代码块缩进 | 不做 ANSI 全屏重绘 |
| `repl.py` | 12 个 `/` 命令、Tab 补全、提示符、模型/档位生命周期、单轮对话错误处理、`confirm_plan` 统一 y/N | 不实现对话协议、不直接执行 Agent 动作 |
| `agent.py` | `vanitas agent`：`AgentLoop` 显式状态机（解析 → 自愈回灌 ≤2 → `max_steps` → 相同动作停滞熔断 @3 → 分级审批 → 工具执行 → `<tool_result>` 回填 → 收尾）；`AgentRepl` 只注入确认/播报/流式钩子；`_clip_feedback` 头 20/尾 40 双端折叠 | 不绕过 `tools` 的沙盒，不实现后台队列 |
| `metrics.py` | token 估算、聊天/翻译预算、汉字计数、耗时/速率、SegmentStat | 不做 I/O |
| `prompts.py` | 模板加载、占位符校验与替换、秒级 `{date}`、`{cwd}` | 不拼请求体 |
| `tools.py` | 人类 `/exec` 原生 shell；`AgentTools` 强类型文件工具、只读 Shell、`is_inside_workspace` 边界；`_execute`/`_execute_shell` 在解码前对 stdout/stderr 各做 512 KiB 字节折叠 | 人类执行与模型工具彻底分离，不做后台任务与自动重试 |
| `translate/` | txt/md/srt 分段、目录递归展开、输出规划、翻译、重组、上下文/预算/清洗、cue 级后处理、文档级实体倒排、失败汇总；对外仍是单一模块（`__init__.py` 全量 re-export） | 不管理服务端、不画终端 UI |
| `translate/types.py` | 数据契约：`Subtitle`/`TranslationOptions`/`T1Budget`/`TranslationOutcome` 等 dataclass 与 `ASR_HALLUCINATION_PATTERNS`/`BOM` | 不 import 任何同级模块 |
| `translate/cleaner.py` | 确定性清洗与写回硬校验：空行折叠、简繁、行首标点、动作括号、斜杠收敛、假名/伪影拦截 | 不解析结构、不调模型、不持有状态 |
| `translate/format.py` | `parse_srt`/`rebuild_srt`/`split_prose`/`chunk_text`/EOL 归一化与探测 | 不判断译文质量、不碰文件系统 |
| `translate/window.py` | `[#N]` 解析、每窗重新编号恢复、`align_window_response` 三态对齐（可用/缺项/灾难）、`identify_suspicious_cues` 逐 cue 定位（空译/超短/同译成对/跨窗复制/编号泄漏） | 不重译、不写回、不持预算 |
| `translate/entity.py` | `DynamicEntityEngine`：敬称名/明确姓名/共同前缀种子、变体聚类、前文示例与锁定名替换 | 不改写整句、不做通用清洗 |
| `translate/io.py` | 输入展开、`--out-dir` 层级、输出冲突阻断、文件名占位符遮罩与两阶段改名 | 不读字幕语义、不调模型 |
| `translate/critique.py` | P3 定向复审：`triage_cue_risk` 纯 CPU 分流、`CritiqueBudget` 双层熔断、`execute_critique_repair` 隔离调用与候选验收（默认关闭） | 不写回、不写滑动上下文、不 import pipeline |
| `translate/engine.py` | `TranslationEngine`：滑动上下文、预算门禁、截断二分重译、**流式消费与 `StreamingAbortDetector` 早停**、文件名翻译、`critique` 复审通道、`build_chat_for` | 不认识 SRT/cue、不做审计 |
| `translate/pipeline.py` | `translate_file`/`translate_srt`/`translate_prose` 串联：语域、实体、合流、**局部回退**（只补损坏 cue；半数及以上损坏或结构灾难才整窗熔断）、P3 复审挂载、**`.part.srt` 增量快照与 `--resume`**、审计重译、T1 预算、失败汇总 | 不实现清洗/解析/路径规则 |
| `monitor.py` | 翻译文件级头部、N 段环形看板、ANSI 局部重绘、批处理汇总报告 | 不依赖 translate 业务逻辑 |
| `batch.py` | JSONL 解析、逐行执行、结果落盘 | 不重试失败行 |
| `ui.py` | 颜色名 → ANSI、符号前缀、VT 开关、Palette | 不 import 任何业务模块、不 `print` |
| `progress.py` | TTY 覆盖式单行进度（`\r` + 擦除），非 TTY 静默 | 不依赖 config/repl/launcher，只依赖 ui |
| `errors.py` | 统一异常类型与 `retryable` 语义 | 不打印、不退出 |

## 5. 配置契约

### 5.1 `config/models.json`

字段名固定；新增模型**只允许追加 `models[]` 条目**，不得改 schema。

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `id` | string | CLI 使用的短名（`serve <id>`、`--model`），唯一 |
| `display` | string | 人类可读名称，只用于展示 |
| `path` | string | 相对仓库根或绝对路径；分片模型必须指向 `-00001-of-0000N` 首片 |
| `port` | int | 默认端口，唯一；`VANITAS_PORT` 可覆盖 |
| `alias` | string | `-a` 参数与 `/v1/models` 的 id，唯一，不带分片后缀 |
| `shards` | int | 分片数；`>1` 时文件名必须与 `path` 的分片模式一致 |
| `role` | string | `general` / `light` / `translate` / `baseline`（当前库存只用前三类） |
| `template_kwargs` | object | 原样注入 `chat_template_kwargs`（标量值） |
| `profiles` | object | 档位表，键为数字串；每档 `ctx/kv_k/kv_v/desc` |
| `default_profile` | string | 默认档位键 |
| `repeat_penalty` | number? | 可选，默认 `1.0`；仅 `>1.0` 时注入请求体（例如 1.1 抑制重复） |

校验规则（失败一律 `ConfigError` → 退出码 `2`）：`version == 1`；id/port/alias 唯一；档位键为数字串且默认档位存在；KV 类型在 `f32/f16/bf16/q8_0/q4_0/q4_1/q5_0/q5_1/iq4_nl` 内；分片命名与 `shards` 自洽；`path` 解析为绝对路径；`repeat_penalty >= 1.0`；未知字段直接报错（防手误）。

生效优先级：`--profile` > `VANITAS_PROFILE` > `default_profile`；端口：`VANITAS_PORT` > `models[].port`；配置目录：`--config-dir` > `VANITAS_CONFIG_DIR` > `<仓库根>/config`。

CLI 文件路径（`translate` 输入/`--out-dir`、`batch` JSONL、`--system`、`--config-dir`）的相对路径按 `VANITAS_ORIG_CWD` 解析；`vanitas.bat` 只负责记录该值并切仓库根，不改变用户对相对路径的预期。

### 5.2 `config/settings.json`

| 段 | 字段 | 语义 |
| :--- | :--- | :--- |
| 顶层 | `version` / `host` | 配置版本；监听地址（只允许回环） |
| `defaults` | `agent` / `chat` / `translate` / `batch` | 各模式默认模型 id；缺省回落 role（agent/chat/batch=general，translate=translate）；`serve` 仍须显式模型 |
| `request` | `timeout_sec` / `max_retries` / `backoff_base_ms` / `backoff_jitter_ms` | HTTP 读超时、最大重试、退避基数、抖动上限 |
| `launcher` | `health_timeout_sec` / `health_poll_interval_ms` / `kill_wait_sec` | 就绪等待、轮询间隔、停止等待 |
| `repl` | `history_file` / `max_context_tokens` / `stream` / `context_reserve_tokens` / `min_output_tokens` / `ctx_warn_pct` / `ctx_danger_pct` / `status_bar_width` | 历史文件、上下文上限、是否流式、历史预留与最低输出；提示符/状态条阈值（默认 60/80）与条宽（默认 20） |
| `agent` | `max_steps` / `max_batch_actions` / `max_feedback_chars` / `max_parse_retries` / `stagnation_limit` / `feedback_head_lines` / `feedback_tail_lines` / 审批集合 | 步数、批量、反馈总上限、解析自愈次数、熔断阈值、反馈头尾行数与动作审批 |
| `tools` | `exec_enabled` / `exec_require_confirm` / 文件与 Shell 策略 | 人类 `/exec` 开关与确认；`readonly_shell_prefixes`、文件限制、写参数黑名单只约束 AgentTools；`max_capture_bytes` 控制子进程输出字节硬截断（默认 512 KiB）；`manual_exec_prefixes`/`destructive_commands` 保留为历史配置，不再限制人类 `/exec` |
| `translate` | `source_suffixes` / `chunk_chars` / `output_suffix` / `context_window` / `context_summary_chars` / `min_output_tokens` / `output_ratio` / `prompt_safety_tokens` / `monitor_lines` / `default_preset` / `environment` / `strip_trailing_periods` / `presets` | 支持扩展名、分块、输出后缀、滑动上下文、摘要长度、翻译输出预算、提示词安全余量、看板行数、生产/实验模板选择、短句句末句号剥离开关；预设含 `task_template` / `window_size` / `max_window_chars` |
| `ui` | `color` / `theme` | 上色模式（`auto`/`always`/`never`）与 7 键主题；整段可缺省，缺省回落默认 |

`ui.theme` 的 7 个键（`prompt/success/error/warn/info/muted/accent`）必须同时给出，取值限 17 个颜色名；`vanitas/config.py` 与 `vanitas/ui.py` 各存一份 `COLOR_NAMES` 并由单测锁定一致（config 不反向依赖 ui，避免循环）。

`/exec` 的子进程超时复用 `request.timeout_sec`，不另设字段，避免 schema 漂移。

### 5.3 `config/prompts/`

只认 `{input}`、`{context}`、`{context_history}`、`{date}`、`{model}`、`{cwd}` 六个占位符。`task_*.md` 必须含 `{input}`；未知占位符、空模板、路径穿越（`../`、大写名）在启动前报错。`{date}` 为秒级本地时间；`{cwd}` 由 `Session.build_user_message` 注入，优先取 `VANITAS_ORIG_CWD`，其次显式参数，最后进程 CWD；`task_translate.md` 用 `{context_history}` 接收滑动上下文；`system_default.md` 作为默认系统提示；`/system`、`/task` 可在会话内覆盖。

模板语义分块：`task_chat` / `task_code` / `task_agent` / `task_translate_asmr` 使用 XML 风格标签（`<role_definition>`、`<guidelines>`、`<engineering_discipline>`、`<sandbox_policy>`、`<tool_definitions>`、`<protocol_contract>`、`<operational_directives>`、`<task_objective>`；ASMR 模板另用 `<asmr_domain_lexicon>`、`<asr_repair_protocol>`、`<sfx_and_staging_rules>`、`<io_contract>`）；`task_translate` 与 `agent_continue` 保持纯文本/紧凑中文提醒，`system_default` 保持纯文本准则。格式按模型选择，不追求“全量 XML”：HY-MT2 的通用翻译继续使用已验证的纯文本提示。运行时变量 `{date}` / `{model}` / `{cwd}` 统一位于静态规则之后的运行时块，`{input}` 最后；`system_default` 由 `prompts.system_prompt()` 校验不得含占位符。六占位符、`task_*` 必须含 `{input}` 与路径穿越拒绝规则不变。

## 6. 进程、端口与守卫

### 6.1 端口分配

| 模型 | 端口 | 档位（默认） | 用途 |
| :--- | :-: | :--- | :--- |
| `qwen_coder` | 4060 | 8K + Q8_0 | Agent 默认主力 |
| `qwen7b` | 4063 | 4K + Q8_0 | chat/batch 默认；通用后备 |
| `minicpm` | 4061 | 8K + F16 | 轻量 |
| `hymt` | 4062 | 4K + Q8_0 | 翻译 |

默认分工由 `settings.defaults` 显式指定：Agent=`qwen_coder`，chat=`qwen7b`（非 Coder 通用），translate=`hymt`，batch=`qwen7b`；`qwen7b` 仍在 4063，minicpm 为 `role=light`。`serve <id>` 必须显式模型；显式 `--model` 覆盖默认。

不得复用 8080 段（Steam 等桌面进程常占）。单实例：启动新模型前由守卫回收所有 `llama-server.exe`。

### 6.2 启动参数（逐字固定）

```text
llama-server.exe -m <path> --host <host> --port <port> -c <ctx> -ngl 999 -np 1
                 -fa on -ctk <kv_k> -ctv <kv_v> -a <alias> -fit off --metrics
```

`-fa on`、`-fit off`、`-np 1`、`-a`、`--metrics`、分片只传首片都是硬语义，不得在重构中「顺手优化」。

### 6.3 守卫

顺序固定：**运行时（4 个 DLL）→ 模型（存在/分片/体积/GGUF magic）→ 回收旧实例 → 端口**。先验模型再杀旧实例，避免目标不可用时误伤正在服务的实例；端口仍被占则报 PID 与映像名，由操作者决策。

| 退出码 | 含义 | stderr 首行（人读） |
| :-: | :--- | :--- |

## 7. 客户端（engine）

- 只用 `/v1/chat/completions`、`/v1/models`、`/health`；`urllib` 全部走 `ProxyHandler({})`，避免系统代理劫持 `127.0.0.1`。
- 超时：连接与读分别可控，默认 `request.timeout_sec`；健康检查固定短超时、不重试。
- 重试矩阵：连接错误 / 超时 / 5xx 重试；4xx 与协议不合法不重试（`EngineError.retryable=False`）。退避 `base * 2^i + U(0, jitter)`，上限由 `max_retries` 控制。
- 流式：逐行解析 `data:`，`[DONE]` 收尾；记录 TTFT、tokens、耗时、`usage`、`timings`、`finish_reason`，done 事件统一给出 `tokens/tps/tps_source`。
- 首字前失败可重试，已输出后不再重试（避免重复内容）；`on_progress` 约 200ms 节流回报即时估算速率，事件中明确 token 为估算值。
- 请求体固定注入 `chat_template_kwargs`（来自模型配置，空对象不注入）；`enable_thinking=false` 对 MiniCPM5 是必需项；`repeat_penalty > 1.0` 时注入同名采样字段。
- 指标口径：吞吐优先服务端 `timings.predicted_per_second`，其次 `usage.completion_tokens / elapsed`；SSE 分片数不是 token，禁止拿来算 t/s。
- `client.py::LlamaClient` 是业务门面（`stream_chat`/`stream_completion`），`engine.py` 是唯一传输层，避免双份 HTTP 实现。

## 8. 交互契约（REPL）

无子命令时 `HANDLERS[None]` 直接分派 `_cmd_agent`，因此 `vanitas` 与 `vanitas agent` 等价；`vanitas chat` 才进入纯 REPL。

命令解析：仅「以 `/` 开头且第 2 个字符不是空格」的行视为命令；其余整行都是用户输入。

| 命令 | 参数 | 行为 |
| :--- | :--- | :--- |
| `/help` | — | 由命令表自动生成 |
| `/model` | `[id]` | 无参列出 4 个模型与运行态；带参切换并写入 `last_used_model`/档位偏好 |
| `/profile` | `[N]` | 查看当前/待生效档位；设置立即原子写入 `preferences.json`，提示 `/restart` |
| `/restart` | — | `/reload` 别名；未保存会话 `[Y/n/c]` 拦截，停旧启新并重绑客户端 |
| `/system` | `[text\|file]` | 设置系统提示；参数是存在的文件则读文件 |
| `/task` | `[name]` | 应用 `task_<name>.md`，每轮输入填入 `{input}` |
| `/clear` | — | 清空消息，保留系统提示与任务 |
| `/undo` | — | `/pop`/`/rollback` 别名；删除最近 user 及其后 assistant/tool_result，释放 tokens |
| `/save` | `[path]` | 保存会话 JSON（默认 `~/.vanitas/sessions/<时间>.json`） |
| `/load` | `<path>` | 加载会话，恢复模型/档位 |
| `/exec` / `!cmd` | `<cmd>` | 人类原生 `shell=True`：无白名单/目录限制，支持管道/重定向；保留超时与 512 KiB 抓取上限 |
| `/stop` | — | `/kill` 别名；仅停止服务端，留在控制台 |
| `/shutdown` | — | `/halt` 别名；保存会话 + 停服务 + 退出（`/exit all` 同义） |
| `/status` | — | 模型/档位/端口/视窗进度条/GPU/PID-RSS-uptime/TTFT-tps/Agent 步数/空闲倒计时 |
| `/quit` | — | 退出（`/exit` 别名；后台服务保留） |

- 提示符 `<id>@<档位> [ctx: N% | Xk/Yk] › `（Agent/chat 默认 `qwen_coder@1`；60% 黄色、80% 红色；休眠态追加 `[休眠]`；`›` 后带一个空格）；TTY 且有 `prompt_toolkit` 时启用历史、行编辑与 Tab 补全（命令/别名、`/model ` id、`/profile ` 档位），否则降级 `input()`；非 TTY 的提示符写 stderr，stdout 只留回答。
- 档位状态：`self.profile` 只代表当前服务端实际档位；`/profile N` 写入待生效档位与 `~/.vanitas/preferences.json`，当前请求预算不会凭空改变；`/restart` 才热重启生效。
- 偏好优先级：`--profile`（CLI）> `VANITAS_PROFILE`（环境）> `preferred_profiles[model]`（偏好）> `models.json::default_profile`；偏好文件损坏/档位失效时回落到默认，不阻断启动。
- 生命周期：`IdleWatchdog` 单守护线程每 10s 检查；空闲 600s 且有服务时，脏会话先原子写 `~/.vanitas/sessions/autosave.json`，再 `stop_all()` 并置休眠；下一次输入在 `_run_chat` 内自动唤醒。`/restart` 与 `/shutdown` 均通过状态锁与看门狗 pause/resume 避免热重启竞争。
- 上下文预算：`budget = max(256, min(档位 ctx, repl.max_context_tokens) - repl.context_reserve_tokens)`；超预算时从最早的用户/助手对开始丢，并打印 `⚠ 上下文已满，丢弃最早 N 轮对话`。不实现自动摘要。
- 瞬态观测折叠：`Session.collapse_intermediate_observations(budget)` 在超 `context_collapse_ratio`（默认 0.65）时，把早于最近 `keep_rounds`（默认 2）轮、长度 ≥1000 的旧 `<tool_result>` 替换为折叠锚点；`<tool_call>` 动作签名与最近两轮不折叠，折叠后置脏。
- 静态前缀：`system_default` 不含 `{date}`；运行时日期位于 `task_agent` 的用户任务模板，避免秒级时间戳击穿 KV Cache 前缀。
- 单轮输出预算：`max(repl.min_output_tokens, 档位 ctx - 历史 tokens - repl.context_reserve_tokens)`；`ChatRunner` 负责统一计算。
- 渲染：增量写 stdout 并 flush；代码围栏内 4 空格缩进，围栏标记不上屏；结束后打印 `· token 数 · 耗时 · t/s`，`-v` 追加首字，`finish_reason=length` 追加截断警告。
- 中断：Ctrl+C 由 `ChatRunner` 捕获，pop 最后 user、不写 assistant；REPL 打印 `⚠ 已中止生成`。
- 等待反馈：加载期 `⋯ 正在加载模型 Ns`、生成首字前 `⋯ 正在生成 Ns`、翻译逐段由 `monitor.py` 的 5 段看板负责；全部走 stderr，非 TTY 自动静默。
- 输出约定：`✓` 成功 / `✗` 失败 / `⚠` 警告 / `⋯` 进行中 / `·` 元信息；状态列统一为 `✓ 运行`、`✗ 停止`、`⚠ 残留`、`✓ 就绪`，提示行也使用 `·` 前缀；颜色由 `ui` 段控制，经 `Palette` 统一上色，源码中不出现 ANSI 字面量。
- Agent：默认模型来自 `settings.defaults.agent`（当前 qwen_coder）；`vanitas chat` 使用 `settings.defaults.chat`（当前 qwen7b）；translate 使用 `settings.defaults.translate`（hymt），batch 使用 `settings.defaults.batch`（qwen7b）。默认 `vanitas` 与 `vanitas agent` 固定 `task_agent`，模型优先输出 `<tool_call>[...]</tool_call>`，同时兼容裸单动作对象/数组；`AgentRepl` 对单动作与只读数组自动执行，对含 `write_file/delete_file/move_file` 的动作展示清单并只弹一次 `[y/N]`。执行结果与 `ToolDenied` 均以 `<tool_result>` 作为 `role=user` 追加，再自动请求下一轮；模型输出普通文本即结束。单次输入步数由 `settings.agent.max_steps` 控制（默认 10）；坏 JSON 中止，用户拒绝不执行，越界转失败反馈。`extract_tool_calls` 优先解析标签，失败后用 `JSONDecoder.raw_decode()` 与栈平衡扫描恢复多对象/尾部垃圾，并对路径字段的未转义 Windows 反斜杠做有限修复，避免 `Extra data`、`Invalid \escape` 或“打印 JSON 但不执行”。最终自然语言通过 `_AgentAnswerStream` 增量上屏，标签与动作 JSON 不落屏；首轮完整模板、后续输入用 `【Agent 继续】` 短提醒控制上下文。

- Agent 调度已从 REPL 剥离为 `AgentLoop`：`AgentRepl._chat` 只注入 `converse/confirm/announce/execute/finalize` 五个钩子，状态迁移由 `AgentLoop.run` 承担。拓扑：

  ```text
  解析 <tool_call> / 裸 JSON
    ├─ ValueError → 自愈回灌（≤2 次，结构化 <tool_result> + 纠偏要求）→ 重试
    ├─ 无动作 → 收尾（流式文本 / 抑制 JSON）
    └─ 动作 → max_steps? → 连续/批次/乒乓/周期/频次停滞? → 本轮同参数失败? → 确认/自动执行
         → <tool_result> → 下一轮
  ```

  解析成功即清零自愈计数；停滞签名是 `(action.name, json.dumps(parameters, sort_keys=True))`，检测最近 6 个签名的连续 3 次、A-B-A-B（第 4 步）、A-B-C-A-B-C（第 6 步）、同签名 ≥3 次，以及批次级 3 连/乒乓；命中即硬熔断且本次不执行。失败签名在本轮内持久保留，中间穿插成功的只读动作也不会清空；再次以相同参数提交时不弹 `[y/N]`，直接回填“此前已失败，严禁相同参数重复提交”。`max_steps` 计执行步与失败阻断步。执行反馈用 `_clip_feedback` 保留前 20 行/后 40 行（字符分支 30%/70%），中间标记含「已截断」。
- `/undo`：`Session.pop_last_turn()` 定位最后一条 user，删除其后缀并计算 `message_tokens()` 差值；清理 `AgentLoop` 最近窗口与失败集合，下一次提示符按新百分比渲染。

## 9. 翻译与批处理

`.txt` / `.md`：按空行分段，段内超过 `chunk_chars` 时优先在句末标点切，其次空格，最后硬切；段落前后空白原样保留，段间空行数量不变。

`.srt`：按空行分块，校验「序号 + 时间轴」；只翻字幕文本，多行字幕整体一次请求并保留行结构；重排序号、时间轴、空行与换行风格，检测到 BOM 则写回 BOM。

微批次合流（Cue-Windowed Pipeline）：`translate_srt` 接受 `window_size`（默认 1）与 `max_window_chars`（默认 250）。窗口内拼成 `[#序号] 台词` 多行请求，`parse_window_response` 校验缺失、多翻、重复与乱序；任一项失败即整窗回退逐句，不采用部分译文；`on_segment` 每窗一次、单调递增。`window_size=1` 严格保持旧逐句行为。编号完整但语义错位的窗口另由 `_window_translation_is_suspicious()` 拦截：正文残留 `[#N]`、非空原文对应空译文，或不同原文得到相同长译文时，同样整窗回退；逐句回退改为单编号窗口 `[#N] 原文` 并解析单编号输出，避免无编号裸文本被模型续写相邻行；多编号/多行单句回退记失败并保留原文。**批次响应必须保留 `[#N]`**：`sanitize_translation_output()` 不再全局删除编号，编号只在 cue 边界由 `strip_window_id_prefix()`/`postprocess_cue_text()` 清理；否则批次解析会退化为逐句并可能合并相邻译文。

混合换行：`parse_srt` 使用 `splitlines()` 识别 CRLF/LF/CR；`rebuild_srt` 对正文、未识别块与块间 separator 统一目标 EOL，混合行尾不再 0 段静默写回。

ASMR 领域特化：`--preset asmr` 经 `settings.translate.presets` 选择 `task_translate_asmr.md`，同时读取 `window_size=6` / `max_window_chars=250`。模板覆盖 ASR 片尾幻觉与循环套话清洗、音近错词推演、口吃保留、拟声词转译、全角动作括号与 `[#序号]` 输出契约；`<asmr_domain_lexicon>` 固化采耳道具、解剖方位、互动动作、情境用语与声效词五类正译/负例（`梵天`、`膝枕`、`浅いところ`、`オマケ`、`お騒がせ` 等），保留 `梵天`/`膝枕`/`添寝`/`特典` 等圈内固有词并给出自然搭配，避免过度意译；`<sensory_immersion>` 追加贴耳体感、体感具象、动作本土化与跨行语流；同一作品内术语保持一致；对齐失败由单句串行自愈回退保证时间轴/序号不漂移。硬清洗在合流前完成：命中 `ご視聴ありがとうございました`、`チャンネル登録`、`高評価`、`ベルマーク`、`Thank you for watching`、`Please subscribe`、`Sous-titres` 的块置空、不耗 token、保留序号/时间轴；空正文写回不追加末尾换行，避免三连换行打乱下一块。输出契约按“K 个 `[#N]` 编号项”校验，不按物理行数：一个编号项可含多行正文；清洗为空时输出 `[#N]` 空正文，禁止删除、新增、合并或重排编号。模型若每窗从 `[#1]` 重新编号，`recover_window_response()` 仅在编号为 `1..K`、无重复且数量一致时按位置重映射；乱序、缺项、多翻仍整体回退。逐句回退时 `strip_window_id_prefix()` 清理译文任意位置的 `[#N]`，并拒绝多编号/多行单句回退，保留原文。

文档级实体与 cue 级后处理（2026-10-29，质量回归修订）：`translate_srt` 在 `window_size>1` 时构建 `DynamicEntityEngine`，只以敬称名、`という名`/`役` 明确姓名与“3–4 字汉字块共同前缀”为种子；裸片假名、拟声词、普通名词不建实体，停用表拦截 `トラック`/`セックス`/`バイバイ`/`コショコショ` 等。变体只允许同首字符前缀；`チン` 不再吞并 `ノア`，`パチンコ` 不进入 `ノア` 变体。`capture_translations()` 只保存洁净示例，`_extract_locked_name()` 只锁高置信裸名，`enforce_locks()` 只替换未翻译日文专名；平假名写法（`みさきひより`）仅在规范键命中明确姓名（`ミサキヒヨリ`）时作为别名。`get_query_context()` 把实体变体、锁定名、示例注入 `<reference_context>`，与 `_context_text()` 叠加而不是替换。`postprocess_cue_text()` 在 cue 边界做简繁、行首标点、重复句号与未授权动作括号清洗，并折叠连续空行；`validate_cue_translation()` 在写回前拒绝空行、假名、`SEXPAR`/`Track`、中日文斜杠；批次失败整窗回退，单句失败保留原文并记 `TranslationFailure`。二者都不触碰序号/时间轴。

## 10. 工具执行安全模型

- 人类 `/exec` / `!cmd`：`exec_enabled` 总开关与 `exec_require_confirm` 确认保留；命令以原生 `shell=True` 交给系统 shell，**不再匹配 `manual_exec_prefixes`、不再做目录/破坏性路径拦截**，支持管道与重定向。工作目录优先 `VANITAS_ORIG_CWD`；超时复用 `request.timeout_sec`，stdout/stderr 仍做 512 KiB 字节折叠。
- Agent 工具与人类 `/exec` 完全分离：前者继续走只读白名单、`is_inside_workspace` 与写参数黑名单；后者的开放不会降低 `AgentTools` 的沙箱边界。
- Agent 工具：`AgentTools` 以启动时的用户原 CWD（`VANITAS_ORIG_CWD`，缺省才用 `Path.cwd().resolve()`）为工作区根；文件接口为 `read_file`、`read_file_range`、`grep_workspace`、`patch_file`、`write_file`、`move_file`、`delete_path`（`delete_file` 兼容）、`list_dir`，全部先过 `is_inside_workspace`。`delete_path` 对文件 `unlink`、目录 `rmtree`、符号链接只删链接本身，工作区根与父级硬拒绝。`grep_workspace` 跳过符号链接与忽略目录，逐个 `resolve()` 后复核边界。
- 路径约束：`is_inside_workspace()` 用 `Path.resolve()` 跟随符号链接，再用 `os.path.commonpath` + `normcase` 判断是否在根内；空串、NUL、不同盘符、父目录、绝对越界路径一律拒绝，抛 `ToolDenied`。`raise_on_error=False` 仅用于查询。
- 强类型契约：`read_file` 只接受 UTF-8 文本，大小上限来自 `settings.tools.max_read_bytes`；`write_file` 只接受 `str` 内容；`patch_file` 要求 `search` 唯一命中并保留原 BOM，且只改内容、不改文件名/扩展名；重命名/改扩展名必须 `move_file(src,dst)`；`read_file_range` 1-based 闭区间、`end` 超 EOF 夹取、`start` 超 EOF 拒绝、跨度受 `max_range_lines` 限制；`grep_workspace` 结果受 `max_grep_results`/`max_grep_file_bytes` 限制；`move_file` 校验源/目标并拒绝覆盖已存在目标，源不存在或命中 `settings.tools.move_illegal_chars` 时统一抛 `ToolDenied("源文件不存在或路径非法")`；`delete_path`/`delete_file` 删除文件或递归目录，根目录保护不可绕过；`list_dir` 条数上限来自 `settings.tools.max_list_entries`。
- 提示词契约：`task_agent` 只列 9 个主工具 + `delete_file` 别名；不提供未实现的 `_reason`。批量动作按数组顺序逐项执行、逐项反馈，失败不回滚已成功项，因此是“单轮批量提交”，不是事务。`patch_file` 只要求唯一片段，必要时扩大上下文，不强制固定上下行数；标签不是安全边界，真正的硬约束仍是 `is_inside_workspace`、只读白名单与审批。
- Agent 只读 Shell：前缀白名单来自 `settings.tools.readonly_shell_prefixes`（默认 `dir/ls/type/cat/echo/findstr/find`、`git status/log/diff/show/rev-parse`、`python verify.py`、`python -m unittest` 等）；`python verify.py` 按 `Path(tokens[1]).name` 识别，绝对路径仍逐个走 `is_inside_workspace`；`-exec`、`--output`、`-o`、`-delete`、`-fprint` 等写参数由 `readonly_blocked_flags` / `readonly_blocked_prefixes` 拦截。`dir/type/echo` 由 Python 只读实现，其余命令 `shell=False`，`& | > %` 只作为字面参数，不会串联或重定向。
- 修改类 shell 命令（`ren/rename/move/del/erase/copy/mkdir` 等）不在 Agent 前缀白名单内；提示词要求模型改用 `move_file/delete_file/write_file`。Git 禁止 `-C`、`--git-dir`、`--work-tree`、`--no-index` 等路径改写选项，并关闭 pager 与可选锁。
- 子进程超时复用 `request.timeout_sec`；输出按 UTF-8 → 本地代码页 → `mbcs` 顺序解码。
- 标准流防膨胀：`_execute` 在 `_decode` 前对 `completed.stdout` / `completed.stderr` 各做 512 KiB 折叠（前 1/4 + 后 3/4，插入 `[stdout truncated]` 标记），解码后追加「[... 底层标准输出/错误超出 512 KiB，已在字节流阶段硬截断，丢弃 N 字节 ...]」。捕获仍由 `subprocess.run` 完成，该折叠只限制解码与反馈体积，不限制捕获峰值。
- 反馈双端折叠：`_clip_feedback` 超限时优先保留前 20 行调用概况与后 40 行报错堆栈；行数少时按 30%/70% 字符切分；多行且首尾仍超限时退化为字符切分；中间标记统一含「已截断」，避免单头截断吞掉末尾堆栈。
- 路径约束是参数级防御，不等同于 OS 沙箱；程序内部自行写文件仍需人工判断。
- 不提供后台任务队列、无人值守循环或绕过修改类 `[y/N]` 的二期钩子。

## 11. 显存与档位策略

| 模型 / 档位 | 整卡实测 | 余量 | 结论 |
| :--- | ---: | ---: | :--- |
| Qwen 7B · 4K+Q8_0 | 7,175–7,313 MiB | 约 700–900 MiB | 默认可用 |

## 13. 设计取舍与演进边界

- **为什么 Python 而不是继续堆 bat**：守卫逻辑（分片、netstat、tasklist、JSON）在 bat 里已到可维护性极限；Python 可用标准库表达且可单测。
- **为什么保留 0/1/2/3/4/9 守卫退出码**：已有脚本与验收基准依赖它；CLI 透传为 `3`，并以纯文本消息定位具体原因（v0.4.1 起移除了 `[GUARD-CODE]` 双重契约——机读交给退出码，人读交给符号化消息）。
- **为什么颜色用原生 ANSI + ctypes 开 VT**：`rich`/`colorama` 会让依赖面翻倍，而本项目只需要 16 色与 6 个符号；`ui.py` 成为唯一渲染细节入口，业务模块不感知 ANSI。
- **为什么端口 4060 段**：8080 段长期被桌面进程占用；4060 与显卡型号一致，便于记忆。
- **为什么单实例**：显存余量决定不能并行；单实例也让 `stop`、`status`、pidfile 语义简单。
- **为什么把确认分级**：单轮规划无法完成改名、读取、写入等多步任务；但每一步都确认会让只读勘察和批量改名不可用。闭环改为“单动作与只读数组自动、修改动作确认、含修改的数组一次确认”，仍保留 CWD 沙盒与 `settings.agent.max_steps` 步数上限，不提供后台队列或无人值守模式。
- **为什么文档拆成四份 + AGENTS**：把「架构契约 / 运行事实 / 操作步骤 / 协作规范」分开，各自单一职责，避免一份巨型文档同时承担四种角色。
- **演进触发条件**：只有出现明确的性能瓶颈、第二实现或跨团队协作需求时，才考虑抽象；在此之前保持单层、直接调用。

历史说明：v0.2 及更早由 5 个 `.bat` + PowerShell 守卫实现，v0.3 起被本方案取代；旧脚本与旧任务书已删除，重构前的快照提交仍可通过 git 历史追溯。
